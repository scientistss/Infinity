# 自然星环有限批次验收

## 状态与复现

这是独立新增的领域测试，入口为 `scripts/natural-ring-journey.ts`。本地实现与定向验收基于 `d048d34`（版本 0.6.11-alpha.1，存档 v9/r8），没有修改生产代码、倍率、已有自然成长脚本／golden 或测试配置。以下数值最初来自这个基座，随后在建筑模板候选的 v9/r9 生产源码上重新执行，结果保持一致；当前仍不代表本阶段完整 CI、发布或原生浏览器接续已经通过。建筑模板生产检查点 686ec62 的完整 CI 已成功，当前集成还包含仅测试／文档的 1635bd7 手动保存见证补强。

```sh
node --import tsx scripts/natural-ring-journey.ts > natural-ring-report.json 2> natural-ring-report.log
```

- stdout 始终输出一个完整 JSON 证据报告；正常为 `outcome.status = "passed"`。
- 规则阻塞、计数越界、严格保存差异或意外异常产生 `blocked` 报告和非零退出码，附实际阶段、原因、最后通过的里程碑及当前状态。不会换种子、注入状态或把失败改作跳过。
- stderr 在里程碑立即输出进度，长等待每 1800 游戏秒输出状态。
- 在源码与工作树状态相同的前提下，两次独立固定种子运行的报告和日志应逐字节相同。固定保存信封时间为 2026-10-10 UTC 零点加实际模拟秒数，只是元数据，不改变游戏时间。

这是一条压缩机器执行时间的领域路线。实际经过 **25033 个逐秒 live tick，约 6.954 游戏小时**；不能称为真人连续六小时或浏览器完整游玩。原生 UI 接续导入自然里程碑，是单独的浏览器验收。

## 起点、资源与时间来源

唯一开局是 `createInitialState(20261010, 20261010)`：500M、500C、0D，无研究、票据或手动次数。世界种子固定；星环 RNG 仅按实际发票前进，从不中途替换或搜索结果。

- 复用已有自然成长路线的有界早期建筑顺序，但不导入该脚本，不依赖预付存档，也不改动其 golden。
- 用 `enqueue`、`enqueueResearch` 真实付款并等真实队列完成：研究所 3、能源 1、燃烧 2、脉冲 3、间谍 4、天体物理 1。
- 为能自然支付加注，本路线真实建造重氢罐 4，容量 140000。罐 3 的 75000 容量不足支付本路线 117335D 的首笔加注；没有把价格、仓库或钱包改大。
- 真正制造殖民船，支付实际燃料，等舰队抵达建立 `colony-1`。空货舱使殖民地没有重氢及重氢产量，成为固定付款来源的明确对照。
- 每笔建筑、研究、造船、殖民燃料和加注都有立即付款前后全星球钱包证据。资源和科研只由玩家 API 与 `tick(state, 1, "live")` 前进，没有手动采集、离线补时、`tick(0)` 或时间跳步。
- 真实星环奖品正常结算，逐票完整记录。它们不是预设补贴，也不选择结果；不能把这条路线称为完全没有星环收益的经济基准。

明确上限：总计 28800 live 秒，付费开局含殖民 7200 秒，曲率后 3600 秒，240 个动作，40 张票，1 次付费加注，3 个有限批次。保存及断言不会重置这些计数。某一步不满足真实规则时，在原状态报阻塞。

## 逐张票据与 9→10 解锁

本地运行实际发行 15 张唯一、连续、递增的票：

- #1：第 1631 秒完成真实天体物理 1 成就，发放一次大档开局奖励
- #3：第 5096 秒真实 `topUp`，母星支付 117335D；117340.43009830698D → 5.430098307D，殖民地钱包不变
- 其余 #2、#4–#15：实际信标发行

每次发行记录 `id/source/outcome/issuedAt/operation/rngBefore/rngAfter` 与钱包、手动次数。用纯 `rollOutcome` 重放验证原种子的下一次随机结果；这个核验不发票、不采用重放状态。所有已存票的完整结果保持不变，所有消耗对应原队列前缀、唯一票号和真实计数增量，计数器不回退。

#1–#10 全部通过真实 `revealRun(state, "manual")` 结算。第 16030 秒的保存点保留 `manualRuns = 9`、自动卡未解锁以及待揭示的第十张票；第十次后再执行实际 live tick，第 16031 秒达到 10 次并自然解锁。装配 `auto_runner` 的默认值为 off，尚无批次许可。

## 有限授权、毛扣费与保存后续跑

三次显式许可只包含当时存在的队列前缀、母星 ID、1 注金属的冻结押注和 **19554D** 总预算（当时报价每票 9777D），许可本身不扣钱、不消耗票。

1. **A，完成当前前缀。** 队列已有 #11、#12、#13，只授权 #11/#12。选中真实殖民地，母星仍是固定来源。真实 live 引擎分别结算两票；完成第一票后完整保存读回，继续同一个剩余批次，不能产生新的许可或重计费用。两票完成后自动停机，#13 留在队列。随后真实信标产生 #14，仍不消费、不扩展 A 的 ID 集。
2. **B，明确停止。** 对现有 #13/#14 创建新许可，未消费时调用真实 `stopAutoRunner`；槽和全局批次都关闭。保存读回后，仅把槽开关打开并实际运行两秒，也不会恢复许可或扣费。
3. **C，曲率前仍有余量。** 再明确授权现有 #13/#14，真实引擎只消费 #13，留下 #14 的有效许可，再依法曲率。并非在已完成／已停止批次上假装验证重置失效。

三次自动执行均核对固定来源、冻结押注、票号和消费游标。以母星当时实际经济报价独立核算毛扣费，准确对应批次累计支出与 `betSpent` 增量，再将真实产出、毛扣费和可能的重氢奖品逐项核对母星 Decimal 钱包；另一个星球只允许正常产出，不能付款或收到母星星环奖品。所选种子的三票实际是晶体、晶体、漂流舰，没有重氢中奖抵销支出：

- #11：140000D → 130223D，毛扣 9777D，存满导致本秒产出为零
- #12：130223D + 当秒正常产出 32.59294306986669D − 9777D → 120478.59294306999D
- #13：140000D → 130223D，毛扣 9777D

这是精确比较实际 Decimal 运算结果，不将奖品后的净钱包变化误作毛支出。开关测试另外验证：自然饱和／零产出的钱包在无许可的引擎尝试前后完全不变。

## 曲率后保留进度、清退消费许可

第 23235 游戏秒已有实际终身生产分数，按 `floor(sqrt(expansionScore / PRESTIGE_SCORE_UNIT))` 得到 1 核心。领域评估不修改输入，实际 `prestige` 结果与完整评估候选一致。

曲率前 C 批次仍 armed，已消耗 1/2，剩余 #14，槽开启；曲率后：

- 母星回到 500M/500C/0D，建筑清零，实际殖民地移除，总时钟不变
- 手动 10 次、自动 3 次、卡片解锁、研究、待开奖票及已生成结果保留
- 旧批次保留来源、票 ID、预算、冻结押注、已扣支出和游标，但 `armed=false`
- 所有跑灯槽 disabled，原因是重置后需要重新授权
- 第 25032 秒真实信标发行 #15；它不会恢复旧许可，也不会消费剩余票
- 再手动开槽，执行一秒真实引擎仍不能续权，槽重新关闭

最终剩余 #14/#15，手动仍为 10，自动仍为 3。脚本没有请求第二次曲率，也不声称覆盖第二轮经济重建。

## 保存信封与原生 UI 接力

报告 schema 为 `infinity-natural-ring-journey-v1`。顶层 `sourceSha` 优先取 CI 的 `GITHUB_SHA`，否则取实际 `git HEAD`，并要求它与实际检出的 HEAD 相同；`source` 另记脚本 SHA-256、脚本与整个工作树的 dirty / porcelain 状态。未提交或未跟踪的脚本必须用精确脚本 hash 与状态说明来源，不能仅凭 HEAD 称完整源码已提交。生成的报告文件可能出现在工作树未跟踪项中。原生浏览器应同时核对报告的存档版本／修订与 release，并把报告 `sourceSha` 作为强制的预期 release SHA。顶层还包括版本、种子、来源说明、上限、结论以及 `milestones/actions/events/waits/payments/tickets/batches/autoDebits`。每个 `milestones[]` 带稳定 `name`、`gameSeconds`、快照及可单独导入的 `save` 信封，顶层 `storageKey` 是原生存储键。

17 个保存点各连续严格读回两次，递归比较整个 `serializeState`：所有字段存在性、类型、数值、数组位置和长度必须相同，只允许对象键插入顺序不同。后续状态实际采用读回对象。前 16 个保存点随后继续 live tick；最终点只证明终态读回采用。总计 **34 次全状态读回**。

## 精确提交的浏览器接续

`scripts/browser-natural-ring.py` 读取同一精确提交重新生成的完整报告，不重新制造富档。必须提供报告 SHA-256、匹配的 Git 提交、已跟踪生成器源码哈希和存档修订；源码修改或来源缺失会拒绝。生成物不当作生产源码。

```sh
python scripts/browser-natural-ring.py --url http://127.0.0.1:4173/Infinity/ --report natural-ring-report.json --expected-sha "$GITHUB_SHA" --expected-report-sha256 "$(sha256sum natural-ring-report.json | cut -d' ' -f1)" --output natural-ring-browser-evidence
```

计划验收分为 9 段：320／390／1440 像素下自然第 9→10 次手动跑灯，装配默认关闭，已有票据的明确有限授权、剩余许可的真实刷新、未来票不续入、明确停止及刷新、真实界面曲率和重置后自然信标。HTTP 资源与浏览器实际执行脚本分别核对发布哈希；原生文件、确认与存储保持真实，完整保存状态、固定付款星球和逐次钱包扣款与领域报告对照。

动画段保留原生 performance／RAF／计时器，仅将 Date 的纪元对齐自然档；动画截图前后都必须仍在揭晓且亮灯。自动结算和重置精确对照段明确标为受控游戏时钟，不能称原生实时数小时。两种段落及来源存档单独记录；输出为空目录起步，失败、未完成或超时均非零并保存诊断。本地目前只有领域实跑和独立静态审查，实际浏览器是否通过必须查看本阶段准确 CI 的归档。
