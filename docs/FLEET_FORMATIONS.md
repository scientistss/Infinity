# 命名编成与有限补船

编成保存名称和各类可飞行舰船的目标数量。它是可复用的数量设计，不保存出发星球、任务、目的地、货物或派遣许可。保存、选择和编辑不会造船、派舰或付款。

## 填入派遣数量

在“舰队”页选择编成后，明确点击填入才会复制数量。编成未列出的舰种置零；任务、坐标、速度、货物和充能选项保持原样。数量不会偷偷裁剪到现有库存，实际派遣仍由原舰队规则检查库存、科技、燃料和槽位。

填入后可以继续手动编辑。编成以后改名或改数量，不会改写当前表单或已经出航的舰队；选择编成也不会自动按下派遣。

## 一次有限补船

1. 明确选择本次固定付款和造船星球。
2. 查看各舰种的目标、本地现货、真实已付款待造数量和本次缺额。
3. 核对本次固定新增数量、各子计划独立预算和合计，再确认创建。

缺额只扣除所选星球的现货与真实已付款队列剩余数量。不计其他星球、不计未付款计划，也不计在途舰船；返航后库存可能超过编成目标。在途舰船仍参加原造船安全容量检查，因此有缺额不代表当前可以立即生产。

每个非零缺额创建一条已有类型的造船计划。数量和预算在创建时固定，运输关闭，创建本身不付款。之后每 10 游戏秒按原造船厂、科技、库存、队列和安全容量规则检查实际付费入队。

这是一次新增数量，不是持续维持库存。创建后出航、战损、取消其他队列或离线恢复都不会扩大旧计划。需要再次补船时，重新选择、预览并确认另一份授权。

## 预算、冲突与取消

每项预算等于真实单价乘以本次固定数量，不能在舰种之间借用或自动追加。同一星球同一舰种已有未结束计划时，非零缺额冲突会阻止整组创建；不认领、合并或改写旧计划。整组要么全部登记，要么一项也不登记，失败不消耗任务编号。

预览后若经济缺额、价格、编成版本或创建条件改变，需要重新预览。已付队列完成转成同星球库存而缺额不变，不会因此追加数量。重复确认不能重复创建。

后续版本若调整舰船价格，旧计划不会自动改价或增加预算：未付部分暂停，已经付款的队列继续按原账单完成或退款。暂停、继续、取消和移除仍在“计划”页按真实任务身份处理；完成的舰船不会因取消而倒退。

## 编辑与未用删除

编辑只影响未来使用，修订号递增。每条补船计划保留创建时的名称、舰种配比、版本和单价快照，旧数量、预算和账目不随新设计变化。

只要任何保留计划仍引用该编成，包括旧修订和已结束记录，就不能删除。需要先按原规则结束并明确移除这些记录；不能为删除编成偷偷取消订单、退款或清除历史。全部引用移除后，删除设计不会影响实际舰船。

## 存档与边界

最多 32 个编成，名称最多 64 个 Unicode 字符；每种舰船数量最多 1,000,000，至少有一种正数量。不接受卫星、防御、未知舰种或小数。允许重名，通过稳定编号区分；删除不回收编号。

v9/r8 保存编成和不可变订单来源。旧存档迁移加入空编成库，不从舰船、协议卡或订单推断新授权；真实 r7 的研究模板与此前付款、运输及回执保持原样。升级仍须原件备份、写入和读回成功。

成功导入、重新开始或曲率换世界会退役旧界面授权，并清除从编成填入的派遣数量。失败导入保留当前表单。曲率保留设计但结束旧世界计划，保留其历史引用，不会自动补船；重新开始清空设计库。
