# Atomic multi-planet building-template application

## Approved boundary

Apply one existing building template to an explicit ordered selection of 2–4 distinct currently owned planets. Every newly created finite order retains its own planet, building, target level and metal/crystal/deuterium cap. No wallet pooling, transport, prerequisite completion, automatic replenishment or persistent batch entity is introduced. Save version 9 / revision 14 stays unchanged.

The batch either returns the complete candidate or returns the original state object without changing any field, queue, wallet or identity counter. Registration itself does not pay for or enqueue construction. Ordinary ten-second finite-order passes subsequently pay on the actual local planet.

Read-only quotation uses the same unmodified state for every leaf. Exact template revision, task counter, explicit payer ordering and review key bind authorization. Achieved/covered leaves contribute no new budget. Existing paused or running orders and manual/protocol paid jobs retain their original ownership. All-covered application is an exact no-op.
