# Infinity 普通建筑拆除 A：定稿规格

日期：2026-10-11。状态：本项目本轮规则已定稿，普通拆除 A 正在独立候选实现和验收，尚未发布。前序地形与 IRN 整合版 ac3cce98403bea1e7162bcb4092e4cfeeb448a9a 已通过完整 CI38123216394 并发布；本阶段 r11 仍须自己的完整验收，不沿用前序结果。

## 决策摘要

本轮范围已选 A：人工指定一颗星球的一座普通建筑，每次只拆一级；地形改造器、月球及后期未开放设施不支持。本规格不增加地形撤格账，也不修改其历史容量和授予账。

本阶段采用：按拆后等级的名义成本计拆除费，离子技术每级减费4%、最高减至0；耗时独立于离子折扣，沿用项目建筑时间计算内核。一级拆到零、成本缓和和时间取级的具体规则见第3节，均明确作为本项目新增选择。不要直接把当前等级的 costFor(L) 当拆除费，也不要把打折后的 paid 直接当计时成本。

范围A及下文P/T、一级边界、取消、缺前置可拆、checked transfer、精确取整和锁槽规则均为本轮已选定的项目规则。其中新增数值是本项目设计决定，不称为用户原先逐项规定的数值，也不称为2026 OGame已确证的现行规则。

## 3. 本项目经济规则

记L为拆前等级，K=L−1，I为已完成离子等级。只有L≥1合法；资源只包括金属、晶体、重氢。

### 已完成的取舍

1. **当前级重建价方案，未采用**：费用为costFor(L)，时间为该级建造时间。实现便利，但比历史低一级口径高约一个增长因子，且直接忽略仓库中已有的离子减费方向。即使补离子，仍应说明是主动提高拆除代价，不能宣称OGame原值。
2. **项目适配的低一级价格，已采用**：通常使用当前有效增长因子，保留离子减费；一级拆到零另写清不随成本缓和反向涨价的基线。计算次序和时间与付款拆开，见下文。它延续现有项目成长曲线，但不是OGame逐项复制。
3. **历史公式形状优先，未采用**：全部等级采用未缓和的目录factor，直接使用base×factor^(L−2)再乘离子折扣。较接近S1公式形式，但会使成本缓和对拆除完全无效；本项目需单独解释这项例外，且仍不能据此称当前OGame实测一致。

### 规则P：付款

- q=max(0, 25−min(I,25))/25；离子25及以上收费为0，不能产生负价或资源收益。已完成离子才计入，排队中的研究不算。
- K≥1：每种资源的未取整拆除基价 U=base×effectiveFactor^(K−1)，effectiveFactor沿用max(1.01, def.factor−growthCut)。
- K=0：U=base/def.factor，使用未缓和目录因子。**这是新增的一级边界选择**，沿用历史表达式的反推方向，但未有官方一级实测例证。它避免“成本缓和把因子变小，反而提高倒数拆除费”。不是声称存在建造第0级的报价。
- 实际费= floor(U×q)。每种资源只在最终乘折扣后向下取整；不能先costFor(K)向下取整，再乘q。S1金属矿例子会因此差1单位。
- 使用确认提交时的目录、成本缓和与离子等级；合法提交一次扣费并保存实际付款。期间研究完成、切星或重新打开面板均不重新计费。
- 即使0费用，也要生成稳定工作身份并经过同样确认、时间和互锁。免费不等于瞬时或自动。

### 规则T：时间，属于项目新增设计，官方尚未完整确证

- 计时基价B=floor(U)，不乘离子折扣；因此离子减价乃至免费都不改变时长。
- T=buildSeconds(B, K, def, 开工前机器人等级, 开工前纳米等级)，采用项目既有经济速度600、最短1秒及建筑earlyLevelSpeedup标志。
- K=0时低等级项使用max(4−0/2,1)=4。纳米自身仍不享受低等级加速。拆机器人或纳米时使用拆前真实等级，因为功能在完工前保留。
- 保存总时长和剩余时长，开工后不重算。本项目保留小数秒，不额外引入S1历史说明中的整秒向下取整。
- 新拆除支持 `1 ≤ totalSeconds < 2^33` 秒、`0 ≤ remainingSeconds ≤ totalSeconds`；均须有限并以同一个 Number 完整 JSON 往返，不夹取或重算。报价与reader共享这一界限，超界在付款前明确拒绝。该范围包含仓库32→31金标，binary64相邻间距不超过约0.954微秒；不声称纳秒步长精确累加，不增加持久化补偿字段，也不改变历史升级计时合同。
- 时间验收使用真实RAF步长（含高刷新率）、现有离线/事件分段及部分任务重载。长短实际步长的差异须按实际减法次数和该量级ULP推导误差界，不能以巨大总时长的宽泛相对误差放行；普通短任务仍要求相同完成边界。孤立的亚ULP切片不等于持久停滞，不据此收费失败或扩存档；只有真实路径持续无法推进才作为待修缺陷。
- 选择此规则的理由：施工工作量随同一低一级名义价格规模增长；离子只是手续费折扣，机器人/纳米是时间加速；避免“离子25级把全部工程压成1秒”。这是可解释且可独立测试的项目设计，不声称等于当前官方拆除时长。

### 钱包与数值安全：本阶段新增硬约束

- 真实正步长模拟结算后，拆除剩余若落入引擎既有绝对 `1e−9` 秒事件边界，则归零再由同一真实任务完成。仅用于浮点逐帧累减尾差，不按总时长放大；reader 不把任意小正数改零，外部完成入口仍要求严格0及同job。步长0、负值或NaN不授予完成。30/120/240Hz的一秒任务原失败留下约 `2.08e−16` 至 `2.30e−15` 秒余数；保留该红后绿回归和阈值两侧、超长实际步长对照，不声称纳秒精度。
- 新manual拆除的扣款和退款，所有资源均须使用checked transfer。复用src/game/order-wallet.ts的checkedWalletTransfer语义：每笔正值必须在实际钱包表示中产生正确方向、可安全核对的真实变化；不是只检查钱包显示大于费用。
- 预检全部三种资源后才能原子提交。任一种正值扣/退不可安全表示，整个操作拒绝：其他资源不变、不分配或前移jobId、不创建/移除任务、不消费完成/取消凭证。
- 零额是合法不移动；全零费用仍生成唯一任务并正常计时。不得将表示不出的正价归零，也不得以资源足够掩盖实际扣款没有变化。
- 报价、未折扣计时基价、总时长及所需持久值必须在付款前可安全计算、表示和读回；NaN、Infinity、越界或不能确认的金额/舍入一律拒绝，不能先收费后截断或降为1秒。
- 拆除计算不继承scaledFloor的1e-12相对上调。P的费用和T的基价采用规定的严格向下取整，不给整数值人为加一。无缓和金属仓库32→31、离子0的费用和B均严格为1073741824000金属；1073741824001是错误结果。
- 这些安全要求仅针对新拆除，不借本阶段悄悄改写其他历史manual升级/退款合同。取消始终用保存的实际拆费，不能按最新离子、factor或目录重报。
- 若退款当前不能安全入账，保留任务、计时、等级与钱包，明确显示退款受阻；不得先吞任务再声称已退。玩家可在合法状态调整钱包后重试。

### 严格floor的有界实现合同

拆除专用计算先以BigInt有理数得到P和B，再转换为既有资源类型；不得以浮点Math.pow、epsilon或break_infinity的近似幂充当精确floor。目录base须为非负安全整数，L仍按既有1–1000范围，不另截等级。

分别精确解析目录factor和成本缓和的十进制值，再做有理数减法与最低1.01比较；不能先做JS浮点相减再把尾差当经济参数。当前普通建筑factor为1.5/1.6/1.8/2，成本缓和节点只开关0/0.01，所以缓和后为149/100、159/100、179/100、199/100。L≥2时以N=base×n^(L−2)、D=d^(L−2)表示U；L=1改用未缓和factor的N=base×d、D=n。B=N÷D；P=(N×max(0,25−I))÷(D×25)，均为非负整数除法。不能从已取整B推出P。

实际P字符串必须通过既有订单金额域，并与转换后资源对象的十进制输出精确相等，再通过保存读回。B也须精确可表示、T须满足上述时间域，但B不是实付金额，不把订单预算上限直接套在乘离子折扣前的U上。离子25级的P=0仍校验B/T。任何表示失败拒绝整个报价，不能以两边同时近似的BigNumber相等或宽容钱包比较替代独立整数预期。

### 取消、完成和资源损失

- 完工不返还原建造投入，不产出残料或任何收益。
- 完工前取消退还本次实际拆除费100%，不退“历史建造费”，不补偿已用时间；原等级与格子保持。此取消政策为项目新规则，证据不支持称为OGame原规则。
- 完成只允许实际所属星球的真实任务到点后结算：任务总时长有限且>0，剩余计时已按事件引擎到达0，fromLevel仍与实际等级一致，身份、报价快照和施工互锁合法。未到点不能调用完成入口抢先降级。
- 取消要求真实任务尚未完成且remainingSeconds>0；它不要求到点。剩余0或任务已被真实完成消费时，不退费、不倒转结果。
- 完成后不能取消，只能重新升级并按新报价支付。重复完成、重复取消或过期引用均不能降级或退款第二次。

## 4. 最小完整玩家循环

1. 在建筑页选择一颗固定星球和已完成的可用普通建筑，查看拆一级报价。
2. 核对资源费用、时间、失去的级别、完工不返建造投入，以及仓容/能源/前置影响；拆机器人时明确列出将回锁的协议槽位。
3. 明确确认后立即扣款并开工；取消预览不做任何修改。
4. 完工前保留建筑原功能。真实完成边界才等级−1、已用格−1，消费同一工作身份；总格不变。
5. 玩家用释放的一格建造普通建筑，正常付款、完工、保存重载。

运行限制：本星建筑升级队列必须为空，且没有拆除任务；不设等待拆除队列，不允许升级与拆除混排。拆除期间所有本星新建筑付款入口统一返回非资源阻塞，不会为此发补给。其他星球和无关领域照常推进。

普通拆除不占新格，满格可拆。对旧reader原本接受的已超格状态，允许逐级减少已用格；不能新加“拆后必须已完全低于容量”的障碍。释放一格并不保证超格状态立刻能新建。

### 确认与任务身份

确认固定星球ID、世界/重置身份、建筑、L→K、报价、施工状态及相关容量和冲突快照；还绑定相关协议槽是否开启、配置身份、enabled状态、计算机/机器人/曲率卡槽条件和预览回锁结果。提交重验，变化须重新核对。切星、导入、重置、重复点击、旧对话框回调不能改为另一星球/建筑/级别。资源自然增长不应让核对窗口每帧失效，但付款前必须足够。

## 5. 安全边界

### 仓库和既有前置

- 仓容按拆后等级重新计算，现存超额资源保留；对应自然生产暂停，既有燃烧/消费继续。例：金属仓库1→0容量变10000，完工时库存14000仍为14000。
- 不连锁销毁已建建筑、科研、船舰或防御；未来新付款按当前完成前置检查。
- 拆除本身不要求恢复原建造前置，以免已经满格的星球为了清理必须先新占格。这是已选定、不同于S3船厂示例的**项目新增宽松规则**，不能倒写为原有合同或OGame一致行为。
- 拆除费不增加生产累计、扩张收益或建成统计；历史成就和累计建成数不倒扣。现存资产积分若由真实等级派生，会随等级变化，不制造一笔“退款收益”。

### 实验室、研究网络、船厂与纳米

- 研究队列任何项目尚在付，包括等待项，禁止拆任意星球实验室。任意实验室拆除进行中，禁止新增研究；不改变原有全局互锁。
- IRN候选的协作筛选排除正在拆除的实验室。已付研究的归属、费用、总时长和剩余时长不被重算；未来开工才读取当前协作条件。
- 本星船厂队列非空时禁止拆船厂或纳米。反向在船厂/纳米拆除期间禁止新增本星造船/防御付款。
- 无关建筑拆除不暂停造船，其他星球继续运行。没有任何自动取消、退费、转移批次的处理。

### 导弹井

- siloUsed必须计入已完成和已付款排队导弹，反弹道1槽、星际弹2槽。
- 付款前要求siloUsed≤10×拆后等级；拆除期间新增导弹同样以拆后容量校验。不得完工再删除超额导弹。
- 这延续本项目容量约束；不是称为原版“必须完全清空井”的规则。若选择更严格清空政策，应另作决定，不暗改本条。

### 有限计划、运输、模板和协议

- 同星同建筑存在running或paused有限计划时阻止拆除，提示玩家明确处理；paused不是撤销授权。施工期间也阻止创建/恢复该同目标计划。
- 不替玩家暂停/取消计划、退燃料、转移预算或改目标。其他计划只因本星施工互锁等待；已有在途货物照原合同交付/返航，不重复发船。
- 模板只保存升级意图；编辑、删除、保留模板均不产生拆除权。拆除身份/施工状态进入相关核对键，旧升级报价须退役；已完成计划不因拆后等级变低自动重开。
- 协议不新增拆除动作。同目标冲突检查覆盖所有enabled卡，包括当前锁定槽中的配置；直接升级同建筑及enqueueCheapest对应mines/storage组均须纳入。它们可能在计算机升级、切星或其他解锁后重建，不能因当前不执行而忽略。
- 有上述冲突时要求玩家先明确停用，不由系统自动改卡。锁槽冲突提示必须说明：“当前锁定不执行，重新解锁后可能重建”。施工期间禁止重新启用或改成同目标冲突动作；校验所有正在拆除的匹配建筑，不能切星绕过。
- 卡架随当前星球而非每星独立。计算机研究完成或切星导致槽位解锁时仍守相同规则：解锁只改变可用性，不恢复已停用配置的enabled，不重新装回已清除卡；新的启用/装配/权限修改仍须经过冲突检查。
- 其他已授权升级可能在拆除完成后占用空格，确认应提醒现有自动建造仍可运行；系统不为手动重建暗设额外永久占格权。

### 机器人降级与锁槽：本阶段新增规则

- 槽位数量仍用现有1+floor(本星机器人/2)+floor(帝国计算机/2)+曲率槽位奖励，上限12；拆除不另设卡槽公式。
- 拆除报价明确列出当前与拆后可用槽数、将回锁的玩家可见槽号及其中已有卡。完工前仍按拆前等级可用，实际完成后回锁。
- 回锁保留卡片配置、既有enabled值和相关持久状态；锁槽不执行。系统不能把回锁当作删除配置、停用全部卡或授予新权限。
- 锁槽允许玩家显式停用已有卡或清除卡，以消除潜在冲突；不得启用、新装、拖入/交换装配或修改其触发/条件/动作等权限。不能通过导入、拖动或参数入口绕开。
- 锁槽中明确停用的卡在保存重载、计算机升级或切星重新解锁后保持停用；明确清除后保持空。未显式改变的配置照原样保留，但在锁定期间不执行。
- 停用/清除涉及既有有限星环批次时，同一星环批次按原有停止授权语义处理，不增加额度、不重建批次、不改变无关卡的授权。

**必须覆盖的具体案例：** 无曲率额外槽，计算机0，本星机器人2，初始可用槽1、槽2（玩家编号，槽2对应内部index1）。预览机器人2→1须写明“槽2将锁定”。若槽2有同目标enabled卡，先因冲突拒绝，玩家停用后才可确认拆除。若槽2是无关配置，允许原配置保留至完工回锁，回锁后不执行。此时玩家可明确停用/清除，但尝试启用、新装、改权限必须拒绝。保存重载完整保留上述状态；随后计算机升到2或切换到足以解锁槽2的另一星球，先前停用/清除不得自启或复活。同目标enabled卡即使原在锁槽，也必须在下一次拆除确认前停用；确认键及施工中启用检查不能漏掉这种潜在解锁。

### 排除设施与世界变更

- 地形改造器不可拆；fieldsMax、terraformerFields、terraformerGrantJobFloor不因普通拆除变化。满格、10000格和历史超格均按既有读取语义保留。
