# Infinity — 游戏设计大纲 v0.4

**English.** Infinity is a web idle game about expanding from one barren planet toward the multiverse. Automation is visual protocol cards, not scripts. The name means unbounded expansion, not an Antimatter Dimensions infinity layer. This file is the design source of truth. The repository today is the planet-surface slice described at the end: OGame-style buildings by level with a build queue, storage caps and planet fields (port phase 1), plus a running protocol-card engine.

> 类型：网页放置/增量 · Vite + TypeScript + break_infinity.js（大数走 `src/game/decimal.ts`）
> 核心卖点：**可视化协议卡** × **OGame 式星际扩张**

## 1. 愿景

你是一颗荒芜行星上的殖民指挥官。一开始只能亲手点击开采矿石，随后用协议卡把重复劳动交给机器人：自动建矿、自动调度能源、自动发射殖民舰。行星 → 星系 → 银河 → 宇宙 → 多元宇宙，每扩张一层，规模放大一个量级，角色也从操作员变成设计自动化的人。

与 Antimatter Dimensions 的差别：

- 不做「维度 N 生产维度 N-1」。建筑靠**资源三角 + 能源约束**联系，不靠层层相乘。
- 不设 1.79e308 的 Infinity 墙。重置由玩家选择（发射殖民舰），没有强制硬顶。
- 自动化是自己拼规则，不是买一个 Autobuyer 就结束。
- 每一层都有新的空间单位（星球 / 星系），不只是新的乘数。

### 建筑（OGame 移植 P1）

所有数值按 OGame 社区公式，时间按宇宙速度 **S = 600** 压缩（`perSecond = perHour × S / 3600`）。建筑按**等级**显示和升级，没有 ×10 / 最大。

- 成本：`⌊base × factor^(L−1)⌋`（L 为目标等级）。
- 产量（每小时，再乘能源效率与全局倍率）：金属 `30·L·1.1^L`，晶体 `20·L·1.1^L`，重氢 `10·L·1.1^L·(1.44 − 0.004·T)`（母星 T = 40°C）。
- 耗电：金属矿、晶体矿 `10·L·1.1^L`，重氢合成器 `20·L·1.1^L`。供电：太阳能 `20·L·1.1^L`，核聚变 `30·L·(1.05 + 0.01·能源技术)^L`（耗重氢 `10·L·1.1^L`/小时，重氢见底时降额）。
- 建造时间（小时）：`(金属 + 晶体) / (2500 × max(4 − L/2, 1) × (1 + 机器人) × 2^纳米)`，再除以 S，最短 1 秒。纳米工厂不享受低等级加速。
- 每颗星球 163 格，每级占 1 格。每个产出建筑可在“资源设置”里设 0–100%（步长 10%）。

### 建造队列

每颗星球同时只建 1 项，队列长度 2（1 在建 + 1 等待）。**入队时扣费**，按目标等级定价；取消全额退还，后面同一建筑的订单目标等级 −1 并退差价。时长在开工时按当时的机器人 / 纳米等级计算。前置按已建成等级检查。

P2 起前置恢复研究条件（只看已完成等级）；已经建成的等级不会因为前置不满足被收回。研究实验室在研究进行中不能升级，研究实验室在建造队列里时也不能开始研究。

### 研究（OGame 移植 P2）

整个帝国同一时间只研究 1 项，研究队列长度 = 建造队列长度（2）。入队扣费、取消全退，时长在开工时按当时的研究实验室等级计算：`(金属 + 晶体) / (1000 × (1 + 研究实验室)) 小时 ÷ 研究速度`（研究速度 = S = 600，最短 1 秒）。成本 `⌊base × factor^(L−1)⌋`；天体物理学 factor 1.75 并取整到百位；引力技术不花资源，要求当前能源供给 ≥ `300000 × 3^(L−1)`（不消耗）。研究等级与暗物质在发射殖民舰后保留，进行中的研究随本轮一起清掉。

来源（P2）：每个新成就 +500（`balance.darkMatter.achievementReward`）；深空星环机的暗物质图块（300–400，大档 500–700）与 JACKPOT（1,000–1,800）。暗物质在发射殖民舰后保留，存档字段 `darkMatter`、`items`、`boosters`、`arcade`（v7 内可选字段，旧 v7 存档读作空）。

**暗物质时钟**（`balance.darkMatterPrices.secondsPerOgameHour = 60`）：暗物质的所有价格和道具时长里，1 个 OGame 小时 = 1 分钟游戏时间。如果直接按 S = 600 换算，1 个 OGame 小时只有 6 秒：「完成」一个 1 分钟的建筑要 15,000、2 分钟的要 30,000、不到 5 分钟就撞 72,000 上限，而克拉肯·金只能缩短 36 秒、资源加成只持续 17 分钟，玩家前 150 分钟只攒得到约 7,000 暗物质，等于用不了。换成 1 分钟 = 1 小时后，统一一条规则：

- 买时间（减半 / 完成 / 克拉肯 / 纽特隆 / 底特律）都是每 30 秒 750，道具的好处是顺延到下一项、不受单次上限；OGame 道具原价（3,000 / 10,000 / 26,000）在这个价位下比按钮贵 3–4 倍，所以改成按钮同价。
- 买资源 = 买生产这些资源要等的时间：1 个 OGame 日的产量 = 24 分钟 × 每分钟 1,500 = 36,000（OGame 原价 120,000 在这里比买时间贵 3 倍多）。补给包保持原来的大小（2.4 分钟产量，不让一个 3% 的补给箱超过 JACKPOT）。
- 资源加成保留 OGame 原价和 7 天时长（168 分钟），是要长时间在线才划算的长线投资。

`npm run sim` 会打印每段时间里所有开工项目的「完成」价格（以及按旧换算的价格）和 9,000 暗物质能完成几项。当前模拟：前 60 分钟建造与研究的中位项都只要 750（9,000 可完成 11–12 项）；60–120 分钟建造最长 269 秒 = 6,750、研究中位 92 秒 = 3,000；120–150 分钟最长的金属矿 354 秒 = 9,000。旧换算下同样的项目分别是 67,500 / 23,250 / 72,000。

P3：暗物质「减半 / 完成」也作用于造船厂正在造的那一批（建筑价目，单次上限 72,000）；底特律道具同上表。

延后：军官 / 商人兑换 / 迁移（P4）、换职业（P7）。价格全部可在 `balance.json` 调整。

### 深空星环机（信标版，OGame 移植 P2）

按 `Infinity-ogame-port.md` §8.6 的 P2 范围实现，数值在 `balance.json → arcade`，符号与面板在 `src/data/arcade.ts`，逻辑在 `src/game/arcade.ts`。

- **开放**：天体物理学 1 级。达成「仰望深空」成就时送 1 次至少大档的奖励开奖。
- **开奖次数**：信标每 30 分钟游戏时间攒 1 次（离线也攒，受离线上限约束），信标最多存 3 次；重氢加注价格 = `max(5,000, 每小时重氢产量) × 2^(过去 24 小时游戏时间内的加注次数)`；加注和奖励开奖最多存到 5 次。信标到点是 tick 的切段点，一次长 tick 与多次短 tick 结果一致。
- **预先掷定**：获得开奖次数时就用存档里的随机数状态（mulberry32，一个 uint32）掷好落点、档位、送灯和数值用的随机数；读档不能重掷。奖品数量在揭晓时按当时的帝国状态计算。
- **概率（信标开奖）**：金属陨石 19%（16% + 未开放商船的 3%）、漂流舰 10%（P3 起，从金属陨石的 26% 里分出）、晶簇 13%、重氢云 6%、暗物质 9%、补给箱 3%、空域 27%（海盗、异星眼、黑洞信标列为“—”）、引力乱流 5%、曲速顺流 5%、LUCKY 2%、JACKPOT 1%。海盗旗 / 异星眼（P5）、商船 / 黑洞（P4）图块显示为暗色。普通图块 90% 普通档、10% 大档。
- **奖品**：奖池上限 = OGame 远征阶梯 × (S / 舰队速度 = 5)。P2 还没有积分榜，阶梯先读帝国自己的 OGame 式积分（建筑与研究已花资源 / 1000）。资源 = `min(奖池 × U(0.2,0.5) 或大档 U(0.5,1.0), 帝国 10 分钟产量的金属当量)`，晶体 ÷2、重氢 ÷3；JACKPOT = `min(奖池 × U(1,2), 20 分钟产量)` + 暗物质 1,000–1,800，种类为押注最多的符号，否则按 68/24/8 掷。奖品受仓库剩余容量限制，溢出部分写明。补给箱随机给克拉肯 / 纽特隆 / 底特律 / 资源 +10% / 补给包（大档 2 个）。**漂流舰（P3）**：文档要求“暂用信标的虚拟舰队计价值”，这里取资源奖品的一半（`min(奖池 × 档位, 10 分钟产量) / 2`，对应文档“舰船总价值 = 档位值 / 2”），约 60% 换成从可选舰船里按随机数挑的一种，其余换成最便宜的一种，不够一艘的零头按金属发放。可选舰船 = 阶梯（轻战、小运、重战、大运、巡洋、回收、战列、战巡、轰炸、毁灭者）里前置已满足的全部，加上再高一档，不出死星。舰船直接进星球，不受仓库限制。引力乱流：本次信标冷却 +50%（最多 3 倍）；曲速顺流：冷却退回 50%，够了立即攒 1 次。
- **LUCKY**：送 2 灯 50%、送 3 灯 25%、小三元 15%、开火车 8%（连亮 3–6 格，坏结果忽略）、大三元 2%；送出的灯不停在 LUCKY / JACKPOT / 暗色图块上。
- **押注**：金属陨石 / 晶簇 / 重氢云 / 漂流舰（P3 起，押中发同等价值的舰船，赔率 ×9.0），1 注 = 帝国 5 分钟重氢产量（至少 1,000），每次合计 ≤ 12 注（1 小时产量），开奖时先扣重氢；押中额外得到 `注数 × 1 注重氢 × 3（金属当量）× 0.9 / 概率`。押注常驻，自动开奖沿用。重氢不够时本次不押注。
- **保底**：连续 5 次空域 / 乱流后下一次落在好图块；每 50 次至少 1 次 JACKPOT。只改落点，不改赔率表。
- **表现**：约 3 秒（加速 0.6 秒、匀速、减速 1.2 秒），停格闪烁；有开奖次数时待机跑马灯；「跳过动画」开关（系统减少动态效果时默认开启）；「全部开奖」快速揭晓并列出汇总与明细；最近 50 次条带、命中统计对照赔率表。悬停图块显示单格概率和本次可能的数值。
- **协议卡**：触发 `runsReady`，条件 `runsGte`、`pityGte`，动作 `runLights { 1 | all }`、`setBet`；目录卡「自动跑灯」（手动开奖 10 次解锁）。离线攒到的次数会被自动开完并列进离线汇总。
- **延后**：舰队充能 / 驻留 / 叠加押注 / 商船 / 黑洞（P4）、海盗与异星眼战斗（P5）、音效（未做）。

### 造船厂与防御（OGame 移植 P3）

按 `Infinity-ogame-port.md` §7 实现。数据在 `src/data/units.ts`（14 种舰船、10 种防御，成本 / 结构 / 护盾 / 攻击 / 货舱 / 引擎 / 前置 / 快速射击表），逻辑在 `src/game/shipyard.ts`，参数在 `balance.json → shipyard`。

- **开放**：造船厂 1 级后出现「造船厂」「防御」两页（舰船 / 防御共用一条造船队列，概览页也显示队列）。
- **造船时间**：每个单位 `(金属 + 晶体) / (2500 × (1 + 造船厂) × 2^纳米) 小时 ÷ S`，最短 0.01 秒。按批次下单（单位 × 数量），**下单时扣全款**，逐个完成；队列最多 10 批，单批最多 1,000,000。时长按当前造船厂 / 纳米等级实时计算。
- **暂停**：造船厂或纳米机器人工厂在升级时造船暂停（OGame 规则），其它建筑不影响。
- **取消**：取消一批时没造完的单位（包括正在造的那一个）全额退款。OGame 不允许取消造船，这里为了放置游戏的手感放宽。
- **下单方式**：输入数量「建造」、「最大」（现有资源能造的最多数量）、「补到 N」（已有 + 排队中计入）。
- **太阳能卫星**：每颗供电 `⌊(T_max + 140) / 6⌋`（母星 40°C 时 30），乘全局倍率，计入能源供给；没有产量百分比开关。造卫星时每颗完成都是 tick 的切段点（至少间隔 1 秒），所以长 tick 与短 tick 结果一致。
- **限制**：小型 / 大型护盾罩每种 1 个（排队中计入）；导弹井每级 10 格，反弹道导弹占 1 格、星际导弹占 2 格。
- **显示**：卡片列出拥有 / 排队数量、单价、单个耗时、攻击 / 护盾 / 结构（含武器 / 护盾 / 装甲技术 +10% 每级）、航速（当前引擎 × (1 + 0.1/0.2/0.3 × 引擎等级)）、货舱、前置链和快速射击（克制 / 被克制）。航行（P4）、战斗与导弹（P5）还没有。
- **积分**：已造单位的资源计入帝国积分（星环机奖池阶梯）。
- **成就**：造船厂、第一艘舰船（不含太阳能卫星）、轨道电站（第一颗卫星）、设防（第一座防御），共 22 个。
- **存档 v8**：星球新增 `units`（每种单位的整数数量）和 `shipyardQueue`（`{ unit, count, progress, source }`）。v7 及更早的本地存档重置并提示一次。
- **节奏（`npm run sim`）**：贪心玩家 6.9 分钟造船厂 1 级，8.6 分钟燃烧引擎 1 级，9.8 分钟第一艘轻型战斗机，11.6 分钟第一颗太阳能卫星，12.3 分钟造船厂 2 级，12.6 分钟第一艘小型运输舰；30 分钟约 18 颗卫星、60 分钟约 52 颗。
- **底特律与漂流舰**：见暗物质表与星环机一节。
- **协议卡（P3）**：触发 `shipyardIdle`（造船队列为空，最后一批完成时即时触发），条件 `unitCountLt`（含排队）/ `energyDeficitGte`（计入排队卫星），动作 `buildUnits { unit, count | "max" | { fillTo } | "deficit" }`；目录卡 12「卫星供电」（第一颗卫星解锁）、13「防御维护」（第一座防御解锁）。文档写的是 11 / 12 号，11 号已被「自动跑灯」占用，顺延一位。
- **延后**：舰队页（派遣界面，P4）、舰队航行、货舱加成（P4）；战斗、导弹攻击、防御重建（P5）。

## 5. 协议卡

比喻是指挥中心的协议板。玩家从卡库拖入卡槽，用下拉框填参数，不写代码、不输入表达式。

每张卡读成一句中文：「**当** 建造队列有空位 **若** 金属矿建造时间 < 120 秒 **则** 入队 金属矿 +1 级」。状态灯：绿=已执行，灰=条件不满足，红=资源不足。可单独开关。从上到下是优先级，可拖动排序。

```ts
type Trigger =
  | { kind: "interval"; seconds: number }
  | { kind: "onResource"; res: ResId; gte: string }
  | { kind: "queueIdle" }                       // 建造队列有空位
  | { kind: "storageFull"; res: StoredResId };  // 某资源到达仓库上限
type Condition =
  | { kind: "resourceGte" | "resourceLt"; res: ResId; value: string }
  | { kind: "energyEffLt"; value: number }
  | { kind: "levelLt"; building: BuildingId; value: number }
  | { kind: "costRatioLt"; building: BuildingId; ratio: number }   // 下一级成本 / 库存
  | { kind: "storageGte"; res: StoredResId; ratio: number }        // 库存 / 上限
  | { kind: "queueLenLt"; value: number }
  | { kind: "buildTimeLt"; building: BuildingId; seconds: number };
type Action =
  | { kind: "enqueue"; building: BuildingId; levels: 1 }   // 入队一级，入队时扣费
  | { kind: "setProduction"; building: ProductionBuildingId; pct: number }
  | { kind: "collect" }
  | { kind: "prestige"; minGain: number };
```

引擎在线每 1 秒、离线每 60 秒按卡槽顺序评估；建造完成和资源满仓时也会立刻评估一次事件卡（`queueIdle` / `storageFull`）。每张卡每次最多执行 1 次。数值存字符串，加载时转 `Decimal`。

| 顺序 | 卡片 | 解锁 |
| --- | --- | --- |
| 1 | 自动采集 `collect` | 手动采集 100 次 |
| 2 | 自动建造（间隔 + `enqueue`） | 金属矿 10 级 |
| 3 | 资源阈值 / 建筑等级 | 首次能源不足 |
| 4 | 成本比例 `costRatioLt` | 机器人工厂 1 级 |
| 5 | 能源效率 | 首次重置后 |
| 6 | 自动重置 `prestige` | 累计 10 曲率核心 |
| 7 | 队列调度（`queueIdle` + `enqueue`） | 首次队列跑空，且机器人工厂 ≥ 1 |
| 8 | 产线调节（`storageFull` + `setProduction`） | 首次有资源到达上限 |

| 9 | 研究调度（`researchIdle` + `enqueueResearch`） | 研究实验室 1 级 |
| 10 | 最便宜优先（`enqueueCheapest`：三矿 / 三仓 / 研究） | 计算机技术 2 级 |
| 11 | 自动跑灯（`runsReady` + `runLights` / `setBet`） | 星环机手动开奖 10 次 |
| 12 | 卫星供电（`shipyardIdle` + `energyDeficitGte` + `buildUnits` 补足缺口） | 拥有第 1 颗太阳能卫星 |
| 13 | 防御维护（`shipyardIdle` + `unitCountLt` + `buildUnits` 补到 N） | 造出第 1 座防御设施 |

卡槽：初始 1，机器人工厂每 2 级 +1，计算机技术每 2 级 +1，曲率科技可永久 +1，上限 12（P2 起）。另有 3 个推荐卡组模板。

## 6. 发射殖民舰

- 产出分 `score = 金属累计 + 3×晶体累计 + 10×重氢累计`（本轮）。
- `gain = floor(sqrt(score / 1e6))`。分数不到 1e6 时按钮不可用。
- 按钮显示「可得 X 核心，下一个还需 Y」。
- 清空：金属、晶体、重氢、全部建筑、建造队列、产量百分比；返还开局 500 金属 / 500 晶体（+ 曲率“开局储备”）。
- 保留：曲率核心、曲率科技、研究等级、暗物质、成就、协议卡配置。进行中的研究随本轮清掉。
- 未花费核心：每个 +2% 全局产出（加算）。曲率科技 8 个节点已实装（开局储备、产线翻倍：矿产量与电站供电 ×2、建筑成本因子 −0.01（最低 1.01）、离线上限 +2 小时、永久卡槽 +1、手动采集 ×10、协议预热、航迹加权）。花费后的核心不再提供被动加成。

## 7. 系统目标

- 离线：与在线同一个分段积分 `tick`（在建项目完成、协议评估、满仓 / 见底都会切段），基础上限 **2 小时**，科技可到 8 小时。离线时协议卡每 60 秒评估。回归时汇总资源与“离线期间完成的建造”。
- 成就 22 个已实装（P2 新增研究实验室、首项研究、计算机 4 级、天体物理学、等离子技术；P3 新增造船厂、第一艘舰船、轨道电站、设防），每个 +1% 全局产出。
- 存档：localStorage；导出为带 `version` 的 JSON（当前 v8：P2 的 `research { levels, queue }`、`darkMatter`、可选的 `items` / `boosters` / `arcade`，P3 的 `planet.units` / `planet.shipyardQueue`）。导入失败不得覆盖当前局。大数用十进制字符串，建筑等级为整数。测试期不写迁移：版本号变化时旧存档重置并提示一次。
- 目标目录：`src/core/`、`src/automation/`、`src/prestige/`、`src/save/`、`src/ui/`、`src/data/`。当前代码仍在 `src/game/` 与 `src/ui/`。

## 8. UX

要让玩家看见下一步、看见每张卡为什么执行或没执行、看见每秒产量和重置预览。不要让玩家写代码或表达式。不要把自动化做成一个没有参数的开关。不要套娃相乘。不要藏公式。小于 1e6 用千分位，更大用科学计数。

## 9. 开放问题

能源是比例降效还是硬性停工；+2% 未花费核心会不会让人永远不花；6 个卡槽是否太紧；离线协议卡是完整执行还是简化；星系层的多星球是独立地表还是共享资源池；要不要挑战模式；美术是纯界面还是加星球示意图；副标题要不要写成 Infinity: Expanse 以和 AD 区分。
