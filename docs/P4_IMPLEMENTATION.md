# P4 可玩核心 · v0.5.0-alpha.1

本版本是 P4 的基础交付，不是 P4 全阶段完成。保留 P1–P3 的经济、研究、协议卡、造船与星环机，把第一条空间扩张循环接通：**造殖民船 → 浏览银河 → 配船/装货/计算航程 → 派遣 → 抵达建立殖民地 → 两颗星球独立生产 → 运输补给或部署舰船**。

## 1. 已实现与未开放

| 已实现 | 当前边界 |
| --- | --- |
| 多星球经济 | 每颗星球有独立资源、仓库、建造/造船队列、产量设置、温度与格子；总时间只增加一次 |
| 帝国共享研究 | 订单记录出资星球；切换星球不改变时长或退款归属；星际研究网络可合并符合要求的研究所 |
| 银河浏览 | 5 个银河 × 100 个恒星系 × 15 个位置；首尾环形；NPC 按种子与坐标生成 |
| 四类舰队任务 | 运输、部署、殖民、侦察；预览速度/燃料/货舱；派遣和召回；抵达与返航消息 |
| 殖民 | 天体物理每两级增加一个殖民名额；发出的殖民任务预留名额和坐标；成功抵达消耗一艘殖民船；护航船返回 |
| 事件结算 | 舰队到达加入所有星球共用的事件边界；离线超过上限的时间不推进舰队 |
| UI | 星球切换器、帝国总览、银河、舰队、消息；桌面和移动端布局 |
| 存档 v9 | 严格读取、多星球/在途舰队往返；旧本地存档重置并提示，旧版本导入拒绝且不覆盖当前局 |

**尚未实现**：回收和残骸、深空充能、NPC 经济/积分榜/商人/军官、完整侦察情报、地形改造器与拆除、跨星球协议卡、恒星跃迁与星图树、P5 战斗、后续银河/宇宙重置。第 16 位深空预留，不接受当前四种任务。建筑和星环机的阶段开关仍为 3，避免显示尚无实际规则的功能。

## 2. 核心状态与不变量

`GameState.planets[]` 是唯一的星球状态。`activePlanetId` 只选择当前操作对象，没有重复的 `state.planet` 或顶层库存。`activePlanet`、`withPlanet`、`onPlanet` 集中处理选择、不可变更新和临时星球上下文。

每次模拟先汇总全部星球的经济和队列边界，再按最早事件推进。资源累计进入帝国本轮 `lifetime`，而 `totalTime`、研究、加成到期、信标与协议评估只执行一次。运输卸货是库存转移，不重复记为生产。运输/部署卸货可暂时超过仓库上限，之后自然产出暂停，货物不会被静默截掉。

研究订单新增 `planetId`。费用、退款和主研究所均绑定订单源星球。取消订单后，同一研究后续订单的差价各自退回原出资星球。星际研究网络按等级选择其他符合当前科技前置、且没有排队升级的研究所。当前仍保留保守的全帝国研究期间实验室升级互斥，尚未细分参与网络的实验室。

同一舰队只结算一次。成功出发才原子扣船、扣货和扣油；计算航程不修改状态。抵达处理顺序按舰队 ID 稳定排序；殖民抢占、再次抵达、再次召回不能复制资源或船只。放弃殖民地时，母星、关联在途舰队和关联研究会阻止操作；放弃会丢失该星球所有库存、建筑和单位。

## 3. 数值基线与明确取舍

经济与研究速度仍为 **600**，舰队速度为 **120**，数值旋钮集中在 `src/data/balance.json`。并未导入浏览器自动操作工具作为游戏引擎。

距离采用环形差值：跨银河 `20000 × Δg`；跨恒星系 `2700 + 95 × Δs`；同系 `1000 + 5 × Δp`。速度输入为 10–100 的百分数，单程秒数为：

```text
(10 + 35000 / speedPercent × sqrt(10 × distance / fleetSpeed)) / 120
```

舰队取最慢舰种的实际速度；舰种按已完成研究切换引擎。`d=2795`、`v=5000`、速度 10% 时，单程约 **69.0426 秒**。超空间技术每级增加 **5% 货舱**。舰队槽为 `1 + 计算机等级`，当前运行安全上限 1000；殖民地上限为 `ceil(天体物理等级 / 2)`，不含母星。

燃料使用各舰种相对舰队速度的节流系数，出发时预付往返；**部署也预付往返，召回不退燃料**。这是当前版本的简化政策，不声称完整复刻 OGame 所有燃油细节。携带燃料占用货舱。实际数值以 `quoteFlight` 为准。

新殖民地按种子/坐标生成温度与 120–239 格；位置 1/2/3 的晶体矿加成 40%/30%/20%，6–10 的金属矿加成 17%/23%/35%/23%/17%。只放大矿产，不放大基础产出或耗电。**母星仍固定 [1:50:8]、40°C、163 格，且不享受位置加成**，以保持原有开局节奏。新局宇宙种子目前固定；每局随机出生与宇宙配置界面留待后续。

NPC 是可重复生成的邻居，占位概率为 25%，实际比例会有取样波动；P4 核心侦察只报告目标存在性、名称和派系，不模拟敌方经济、精确舰队或反击。

资源/成本继续用 `break_infinity.js`。**产率、能源、等级、船只数量与事件时长仍有 JavaScript number 边界；宇宙维度和存档集合也有安全上限。当前版本不是无限数值系统已经完成。** 下一阶段需要独立审计所有 `toNumber()` 边界、采用更大数量模型，并实现更高层空间聚合；不能仅把 UI 改为科学计数就称为无限扩展。

## 4. 自动化与重置

当前协议卡只对选中的星球生效；离线时是保存时选中的那颗，不会为每颗殖民地复制一个免费协议机。研究与信标仍为帝国级事件。显式的 `scope`、舰队任务模板及返航触发器尚未加入。

“殖民船”是可派遣的单位，**“发射殖民舰”是既有第一层重置按钮**，两者不是同一个动作。第一层重置会清空全部星球建筑/库存、殖民地、在途舰队与队列，保留研究等级和原有跨轮系统；界面会确认风险。恒星跃迁/星图尚未开放。

## 5. 存档与升级风险

使用原键 `infinity.save.v1`，信封版本升级到 **9**。生产状态只保存 `planets[]`、`activePlanetId`、`universe`、`fleets[]`、`messages[]`、`nextFleetId` 等真实数据，Decimal 写成字符串；研究订单保存源星球 ID。

读取验证包括：唯一星球 ID/坐标、恰好一颗母星、有效选中星球、研究/舰队源星球存在、舰队种类和数量、货物合法、计时一致、唯一舰队 ID、消息长度及安全数量上限。不接受 NaN/Infinity 或卫星/防御伪装成可移动舰队。

**测试期不迁移 v8**：打开旧本地存档会开新局并提示；手动导入 v8 会拒绝，不覆盖当前状态。运行新版本前，应先从旧版本导出备份。v9 不能导入仍在运行 P3 的旧站点。

## 6. 复现验证

推荐 Node.js 22、npm 10，使用锁文件：

```bash
npm ci
npm run build
npm test
npm run sim -- 60
# 含预置资源的双星球测试存档；不是正常开局：
npx tsx scripts/p4-fixture.ts > p4-review-save.json
```

初次完成验证时为 **190 项单元测试 / 11 个测试文件通过**，其中新增 53 项。覆盖并行生产/队列、时间不翻倍、研究源星球/退款/网络、环形距离、舰队输入/舱容/燃料、殖民预留/返航/召回、离线等价与上限、存档严格校验。

60 分钟原贪心策略模拟：首次 `1e6` 扩张分 **23.8 分钟**，天体物理 1 与首次信标开奖 **48.3 分钟**。此策略用于保留 P3 节奏，**尚不自动殖民，不能据此报告首次自然殖民耗时**。

生产包的交互检查：

```bash
# 需要另外安装 Python playwright 和可用 Chromium；不是运行游戏的依赖。
python scripts/browser-dom-smoke.py --fixture p4-review-save.json --output dom-evidence --chromium /usr/bin/chromium
```

该脚本把生产 JS/CSS 内联进隔离 DOM，使用明确的内存 Storage 测试替身和受控时钟；17 项检查覆盖星球切换、银河绕回、表单持久性、航程报价、派遣、DOM 节点稳定性、殖民抵达、消息、旧存档拒绝与桌面/390px 不溢出。**它不是原生 localStorage、HTTP 服务、GitHub Pages 或网络端到端验收。** 当前执行环境禁止浏览器导航，线上浏览器验收仍待可导航环境执行。

## 7. 美术与后续接口

本次继续使用仓库已有原创 WebP/SVG；新星球小图为 CSS 绘制。资源依然遵循 `/Infinity/` base 路径；没有新调用 Google Imagen，也没有声称完成全套素材替换。

规则模块不依赖图片：可在后续单独加入图标清单、统一风格美术、分辨率梯度和构建期资源完整性校验，不需要再重写经济/舰队核心。优先后续交付顺序为：深空充能与回收 → 跨星球协议卡 → NPC 经济/贸易/军官 → 星图重置 → 更高层扩展与数值边界改造。战斗属于 P5，应独立测试和交付。
