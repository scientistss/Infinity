# Infinity 路线图与验收清单

核对日期：2026-10-11。

本清单把现存设计中的玩法、已发布能力和待补机制分开记录，供分阶段开发与验收使用。下一批顺序为：**地形改造器 → 评估星际研究网络的完整参与规则**。普通建筑拆除 A 的规则已形成[独立规格](DEMOLITION.md)，实施须先完成前序候选验收；NPC 经济仍需形成机制规格，不根据一个功能名称直接添加成长曲线或奖励。

- 后续手动运输增量 [f96894e](https://github.com/scientistss/Infinity/commit/f96894eb1b32737ab403890ed83fdb3da41a0644)，版本 **0.6.15-alpha.1 / v9r9**，已通过自己的[完整 CI38112187362](https://github.com/scientistss/Infinity/actions/runs/38112187362)并发布。下文13项已据此更新；其余基线范围不因该增量扩大。地形改造正在独立实施，本文规格不代表其已经验收或发布。
- 依据为仓库中的 [DESIGN.md](DESIGN.md)、[AUTOMATION.md](AUTOMATION.md)、[P4_ORIGINAL_01.md](P4_ORIGINAL_01.md)、[P4_SPACE.md](P4_SPACE.md)、[DEEP_SPACE.md](DEEP_SPACE.md)、当前源码及各增量文档。原始交接全文不在仓库，`Infinity-ogame-port.md` 只有引用；本清单不能声称已逐条覆盖未取得的原文。

- 四类状态为：**已发布**（本条明确范围已进入基线）、**部分**（已有子能力，仍缺闭环或范围）、**未实现**（基线没有该能力，目标可继续细化交付）、**机制未定义**（缺少足以编写行为断言的规则）。这些条目的大小不同，不用条目数或测试数计算完成百分比。

- 后续可以提出标注清楚的“拟定规则”，并记录选择理由与适用范围；不能将它们写成用户已经规定的规则或声称来自缺失原文。

现有代码从真实的原版 P4 多星球与深空基线继续开发，并非空项目。旧 R12 缺少可验证的源码字节，不能将其视为已恢复，也不能用其历史测试数量为本版本背书。不同路线即使使用相同 schema 和修订号，也不自动兼容；具体保护边界见 [SAVE_SESSION.md](SAVE_SESSION.md)。

## A 已发布的回归基线

### 1 地表经济与建设

- **状态：已发布。** 三资源、能源约束、仓库、等级建筑、生产设置及真实付费建造队列。
- **依据：** [DESIGN.md](DESIGN.md) 的地表规则；`src/game/economy.ts`、`queue.ts`、`src/data/buildings.ts`。
- **最小循环：** 生产资源 → 查看成本与前置 → 付款建造 → 完成或取消退款 → 保存后继续生产。
- **依赖：** 资源公式、事件时钟、星球身份、付费工作账本；后续扩容和拆除必须复用这些规则。
- **存档影响：** 后续变更需保留每星库存、建筑、生产设置、已付金额与队列身份；不能用重建队列代替迁移。
- **最低验收：** 独立核对价格、耗时、格子与退款；切星不改变归属；重复完成、取消和重载不复制资源或建筑。

### 2 基础研究 暗物质与单位生产

- **状态：已发布。** 基础研究队列、暗物质道具与资源包、14 类舰船和 10 类防御的生产。研究网络的跨星加速效果另见第 7 项；能制造导弹不等于已能发射攻击。
- **依据：** [DESIGN.md](DESIGN.md)；`src/data/research.ts`、`dark-matter.ts`、`units.ts` 与对应领域模块。
- **最小循环：** 满足前置 → 实际付款 → 排队完成 → 获得研究效果、道具效果或实际单位库存。
- **依赖：** 第 1 项、共享研究与本地造船队列、稳定付款身份。
- **存档影响：** 保留付款星球、研究进度、已付批次、单位与道具库存；新效果不能追改历史账单。
- **最低验收：** 前置、互斥、费用和实际效果一致；造船部分完成后取消只处理剩余部分；切星、重载和离线不重复授予。

### 3 原协议卡与第一层曲率

- **状态：已发布。** 13 张目录卡、规则参数与状态说明；第一层曲率、核心和 8 个曲率科技节点。当前协议机主要作用于选中星球。
- **依据：** [AUTOMATION.md](AUTOMATION.md)、[CURVATURE_PREVIEW.md](CURVATURE_PREVIEW.md)。
- **最小循环：** 解锁卡片 → 装配并设置参数 → 触发或显示等待原因；积累分数 → 查看重置收益与损失 → 明确重置 → 新一轮继续。
- **依赖：** 第 1、2 项、协议求值时钟、共享重置规则和安全存档。
- **存档影响：** 保留已定义的配置和跨轮资产，退役旧世界执行权；新卡片或新语法须独立迁移。
- **最低验收：** 未解锁不能装配；顺序与求值边界不变；预览不执行重置；实际保留与清空符合合同；存储失败时不采用新世界。

### 4 多星球 银河与普通舰队

- **状态：已发布。** 独立资源和本地队列、共享研究、银河浏览、运输、部署、殖民、基础侦察与召回。NPC 当前只有基础占位及身份信息。
- **依据：** [P4_ORIGINAL_01.md](P4_ORIGINAL_01.md)、[P4_SPACE.md](P4_SPACE.md)。
- **最小循环：** 造殖民船 → 浏览空位 → 配船装货并报价 → 派遣 → 实际抵达建殖民地 → 护航返航 → 两星生产与补给。
- **依赖：** 第 1、2 项、坐标与名额预留、航程报价、统一事件边界。
- **存档影响：** 星球、舰队、来源和目标身份稳定；在途和返航状态必须可以完整续跑。
- **最低验收：** 舰船、货物、燃料守恒；殖民抢占按真实规则处理；重复抵达和召回不复制；研究付款不随界面星球改变。

### 5 深空 商人 遭遇战与回收

- **状态：已发布。** 第 16 位驻留 1–3 段、真实事件、返航入库、限时固定报价、黑洞保护、六回合编队聚合遭遇战与残骸回收。不是完整行星战争或 OGame 逐舰随机选靶复刻。
- **依据：** [DEEP_SPACE.md](DEEP_SPACE.md)、[DEEP_DASHBOARD.md](DEEP_DASHBOARD.md)。
- **最小循环：** 派舰 → 驻留与事件 → 实际奖励或战损 → 返航入库 → 查看回放；有残骸时再派回收舰取回。
- **依赖：** 第 2、4 项、确定性随机状态、事件凭证、商人账本和战斗模型。
- **存档影响：** 保存结果、在途奖励、真实损失和结算身份；不能通过回放或读档重新抽取、重复发奖。
- **最低验收：** 发奖时点、返航归属、保护规则、报价有效期和回收竞争可复现；所有库存变化有实际来源。

### 6 有限自动化与安全存档

- **状态：已发布。** SaveSession、有限星环批次、有限订单、单来源补给、建筑与研究意图模板、命名编成与一次补船、费用预览、曲率预览和只读开拓。
- **依据：** [SAVE_SESSION.md](SAVE_SESSION.md)、[LOCAL_ORDERS.md](LOCAL_ORDERS.md)、[TRANSPORT_ORDERS.md](TRANSPORT_ORDERS.md)、[RING_AUTOMATION.md](RING_AUTOMATION.md)、[BUILDING_TEMPLATES.md](BUILDING_TEMPLATES.md)、[RESEARCH_TEMPLATES.md](RESEARCH_TEMPLATES.md)、[FLEET_FORMATIONS.md](FLEET_FORMATIONS.md)、[EXPANSION_NAVIGATION.md](EXPANSION_NAVIGATION.md)。
- **最小循环：** 保存意图 → 新报价并明确预算和来源 → 实际付款或运输 → 达标停止 → 保存后续跑或核对终态。
- **依赖：** 第 1–5 项、稳定任务与工作身份、预算账本、界面权限退役。
- **存档影响：** 迁移保留原件及实际状态，不额外授予物流或自动执行权；跨标签冲突停止覆盖。
- **最低验收：** 只读查看不付款；旧报价、旧节点和旧世界权限不能复活；数量、预算、来源与票据范围不自动扩张；备份、写入或读回失败安全冻结。

## B 部分完成的能力

### 7 星际研究网络

- **状态：部分。** 科技和“联通 L 个额外研究实验室”的文案存在，但基线 `src/game/research.ts` 的 `effectiveLabLevel` 只使用付款星球研究所，多星球加速尚未实现。
- **依据：** `src/data/research.ts`、`src/game/research.ts`、[P4_ORIGINAL_01.md](P4_ORIGINAL_01.md)。[历史 dbadf9e2 的候选实现](https://github.com/scientistss/Infinity/blob/dbadf9e2c7e423611fd75cf22e3cb837cd94cccc/src/game/research.ts)按目标科技门槛筛选未排升级的额外研究所，并按等级取最高 L 座；它不是当前已集成规则或验收证据。
- **最小循环：** 两星建设研究所 → 研究网络 → 在固定付款星球查看缩短的时间 → 实际研究 → 切星并保存重载 → 按正确时长完成。
- **依赖：** 第 2、4、6 项；先评估参与资格、选取顺序、开工快照与实验室互斥。首批不默认取消当前全帝国研究所互斥。
- **存档影响：** 保留旧已开工研究的保存时长、付款和退款归属；新增参与快照时须新格式与迁移。即使不增加字段，也须验证规则语义变更。
- **最低验收：** L=0 和单星与旧版一致；只加入约定数量的合法研究所；只影响时长，不跨星扣款；开工后不因切星重算；模板、有限计划、取消与离线共用同一规则。参与规则尚未定稿，历史算法只能作为候选。

### 8 星系与银河扩张层

- **状态：部分。** 多星球、星球特性、银河地图和运输已存在；恒星跃迁、星图及更高层重置未实现。地图范围不等于重置层级完成。
- **依据：** [DESIGN.md](DESIGN.md) 的扩张层级与 [P4_SPACE.md](P4_SPACE.md)。
- **最小循环：** 当前先维持多星殖民与运输；新增层级须完成该层成长 → 预览 → 重置 → 新资源用途 → 保存续跑。
- **依赖：** 第 4、6 项及第 26 项的明确重置规则。
- **存档影响：** 新层级需要世界身份、跨层资产与旧任务退役语义，不能复用旧星球 ID 继承权限。
- **最低验收：** 空间扩张和重置分别列证据；现有运输与殖民保留；未定义的新收益不进入生产规则。

### 9 自动化覆盖

- **状态：部分。** 选中星球协议和显式授权的有限跨星订单已存在；没有完整的通用 scope、返航触发器、任务模板与持续物流合同。
- **依据：** [AUTOMATION.md](AUTOMATION.md)、[TRANSPORT_ORDERS.md](TRANSPORT_ORDERS.md)、[FLEET_FORMATIONS.md](FLEET_FORMATIONS.md)。
- **最小循环：** 先完成有限跨星目标；新增通用规则时，显式指定作用范围 → 触发 → 真付款或运输 → 停止 → 重载不重复。
- **依赖：** 第 3、4、6 项；详细机制见第 24、25 项。
- **存档影响：** 新 scope、事件游标和许可需版本化；旧有限计划不自动取得持续消费权。
- **最低验收：** 一次补船不被当作库存维持，纯模板不附带执行授权；新能力须证明不会跨星误付、循环重复或超预算。

### 10 数值规模与性能

- **状态：部分。** 库存使用大数，已有表现优化与原生量测；舰船、事件、等级和集合仍有工程上限，不能宣称无限规模或所有设备极限流畅。
- **依据：** [PRESENTATION_PERFORMANCE.md](PRESENTATION_PERFORMANCE.md)、[P4_SPACE.md](P4_SPACE.md)、当前保存校验与容量常量。
- **最小循环：** 声明具体容量 → 合法增长到边界 → 保存与重载 → 继续真实操作和时间推进。
- **依赖：** 第 1–6 项、事件调度、显示与存储容量；扩展数值前先定义资源预算。
- **存档影响：** 放宽整数或集合上限、改用更大数量模型或空间聚合时，需重新定义校验、迁移与旧版拒绝。
- **最低验收：** 用具体规模和设备条件给出正确性、CPU、响应及存储指标；原生输入和持久化成功；不得仅改科学计数显示就称大数改造完成。

### 11 长期成长与平衡

- **状态：部分。** 固定路线验证了新号、一次曲率、第二轮分工和自然十次手动星环；未证明所有策略平衡、第五次曲率基本自动化或真人长时挂机。
- **依据：** [NATURAL_GROWTH_ACCEPTANCE.md](NATURAL_GROWTH_ACCEPTANCE.md)、[NATURAL_RING_ACCEPTANCE.md](NATURAL_RING_ACCEPTANCE.md)、[DESIGN.md](DESIGN.md) 的节奏目标。
- **最小循环：** 既有规则下多轮合法成长 → 每轮明确使用保留能力 → 重建分工 → 记录所需人工操作。
- **依赖：** 第 1–9 项；先定义“第 5 次基本接管”的操作范围与允许人工干预，不先调倍率让测试通过。
- **存档影响：** 验收本身不改存档；若新增统计，只记录必要事实并定义保留与容量。
- **最低验收：** 不注入资源或更换失败种子；逐轮实际付费、来源和保存续跑可追溯；加速领域模拟、局部浏览器接续、真人实时体验分别报告。

### 12 美术与表现覆盖

- **状态：部分。** 原 UI 与素材、15 类独立星环 SVG 已存在；并非所有项目均有独立 Imagen 原画。

- **依赖：** 已要求保留的布局与配色、资源注册和构建完整性检查；新增资产合同见第 27 项。
- **存档影响：** 通常无游戏进度变化；若增加个人显示偏好，应与经济状态分开。
- **最低验收：** 每项资产有准确来源、尺寸与引用；实际像素可见、无遗漏或遮挡；不以风格名称虚报生成来源，不因补素材重做原界面。

## C 后续独立交付项

### 13 手动运输辅助

- **状态：已发布，限普通手动运输。** f96894e 经独立完整CI及真实派遣、配送、返航、保护和四宽验收后发布。
- **依据：** 现有 `src/game/fleet.ts` 航程报价与运输合同；`src/ui/transport-load-model.ts`、[手动运输合同](MANUAL_TRANSPORT.md)及阶段15精确提交记录。
- **最小循环：** 基于实际库存、舰船与货舱获得装载帮助 → 明确填入或调整 → 人工确认派遣 → 真实出航、交付及返航。
- **依赖：** 第 4、6 项、真实燃料与货舱报价、固定来源与过期草稿退役。
- **存档影响：** 纯装载草稿不应变成持久执行权；实际派遣仍产生现有真实舰队。若需要新字段，应另列迁移理由。

### 14 地形改造器

- **状态：未实现。** 数据表已有价目、前置和用途，当前仍未开放及产生扩容效果。下述迁移原则是本轮拟定采用的实施方向，尚未完成生产实现。
- **依据：** `src/data/buildings.ts`：首级 0M／50000C／100000D、能源门槛 1000、系数 2、纳米工厂 1 与能源技术 12、每级增加 5 格；`src/game/planet.ts`：每个建筑等级占 1 格。
- **最小循环：** 还剩 1 格的合法星球满足前置和能源 → 查看真实报价 → 付款入队 → 实际完成 → 用新增格建普通建筑 → 保存重载。

## 地形改造的先决规格与迁移原则

`fieldsMax` 当前直接持久化，读取器接受 1–10000；已知建筑 ID 的非零等级也可被读入。因此不能假设所有旧 r9 档的 `terraformer` 等级为 0，不能按 `5 × 旧等级` 重算容量，也不能从旧容量中盲目减去这个值。

本轮拟定以下迁移原则，字段名和验证细节须在小规格中确定：

1. **旧事实不变。** 迁移时保留旧有效总格 `fieldsMax`、全部等级、钱包和已付队列。新增的“本规则实际授予扩容”账从 0 开始，不回溯发奖或扣格。
2. **新完成才授予。** 新版真实完成一个地形改造等级时，原子增加 5 个有效总格并记录本次授予。使用稳定付费工作身份，重复完成、重载或离线接续不能重复授予。
3. **等级与容量来源分开。** 旧非零等级继续存在，不能当作新版扩容凭证。以后设计拆除时，也不能按总等级盲目扣回容量；必须区分迁移保留的有效容量和新版实际授予。
4. **迁移失败保护原件。** 新格式须备份、完整写后读回并验证旧读取器安全拒绝。无法解释的旧队列不能通过重写等级、取消付费工作或补造新账单来“修复”。

实施前仍需完成下列小规格和独立审查：

- 能源门槛各级如何递增，曲率成本因子是否作用于能源；能源不是可扣除库存。
- 能源在入队、开工的检查时点，以及等待期间变化的处理。
- 当前 10000 总格边界如何在付款前限制；若扩大上限，须同时证明保存、显示与调度合法，不能生成无法重载的新档。
- 旧 r9 已有非零地形改造等级，以及已在付或排队的地形改造工作如何接续；必须保持旧金额、进度与身份，不重新收费。其新版完成是否授予及如何标记，须明确后才能迁移该场景。
- 新授予账的合法范围、与有效容量及等级的交叉校验，以及取消、导入、保护态、曲率和跨星操作的完整矩阵。

旧版本读取器原本支持的规范化与新增迁移造成的改变必须区分：逐字保留原始备份，并单独记录非规范输入的字段差异。对会发生规范化的输入，不能笼统声称全部字段原样不变；也不能添加无依据的拒绝条件，把旧版本原本支持的状态当作损坏。

这些原则不是已通过的迁移报告。方案只有在真实旧格式输入、合法非零等级及相关已付队列都被单独验证后，才能声明对应兼容范围。

## 每阶段共同的完成门槛

1. **规则明确。** 写清输入、费用、收益、停止、取消和异常行为；将既有规则、历史候选和新拟定规则分开。
2. **实际闭环。** 至少一个完整玩家循环，包含真实付款、真实结果、稳定身份，以及有意义的取消、重试、切星和保存续跑。
3. **独立预期。** 金额、数量与容量使用独立固定预期值；同一生产函数与自身对照不能单独证明公式正确。
4. **存档与旧授权。** 真实旧格式迁移、全状态读回、原件保护、旧读取器拒绝和跨世界权限退役；兼容范围逐条写明。
5. **界面与回归。** 原生操作、文件确认、焦点、重复输入和实际可见性；保留全部受影响旧门禁。合成输入、受控时间、自然领域路径和真实设备体验分别说明。
6. **精确提交验收。** 该 SHA 自己的完整 CI 通过，失败运行原样保留；单个子实验成功或测试数量增加不能代替整轮。
7. **发布后再改状态。** 核对部署使用的确切提交、产物与可访问功能后，才能由候选改为已发布；文档完成、分支推送和 CI 通过都不单独等于部署。

新增阶段应在本文件更新对应状态与证据，并在 [REBUILD_CHECKPOINTS.md](REBUILD_CHECKPOINTS.md) 或后续阶段记录中保留准确提交、检查、实际产物及未覆盖边界。没有可证明的原件或规则时，保留缺口，不以其他路线的实现或历史数字填补。
