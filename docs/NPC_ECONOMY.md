# NPC 可侦察经济基线：第一段规格

## 状态与边界

**本规格正在独立候选中接入，目标版本0.6.19-alpha.1／v9r12；尚未完成整体验收或发布。** 本文其余“拟定”标记保留新规则的来源性质，以下历史事实原以准备检查点核对。 来源固定为提交 [`52e7ed83a24f96dbdd240b4e0e4216c63fd90d55`](https://github.com/scientistss/Infinity/commit/52e7ed83a24f96dbdd240b4e0e4216c63fd90d55)。历史准备检查点未修改生产代码、存档修订、构建产物或网站；本次候选接入仍须自己的精确完整CI和产物发布。

本段交付边界为：**一个 NPC 的确定初态 → 独立固定生产与封顶库存 → 真实侦察抵达形成快照 → 再次侦察看到后续变化 → 保存重载一致。**

这只是“可侦察经济基线”，不是完整 NPC 经济、成长、经营或战争系统。不包含 NPC 建筑升级、研究、能源网络、舰船与防御、主动消费、玩家扣减、交易、掠夺、攻击、反击、排名、里程碑或奖励。库存满仓后暂停生产，本段没有将其重新消耗或扩容的玩法。不能据此将路线图中的完整 NPC 经济或行星战争标为完成。

本文以“已有”标记现存合同，以“拟定”标记本段新增规则。没有标为已有的资源率、容量、模型和迁移语义均为拟定，不是 OGame 原版数值，也不是原交接文档已经约定的规则。验收要求见 [NPC 基线验收](NPC_ECONOMY_ACCEPTANCE.md)。

## 2. 拟定经济模型：一个固定生产档

第一段所有合法 NPC 使用同一个 `fixed-production-v1` 档位。派系不改变资源率；不先增加随机档位、初始建筑或升级路线。

| 资源 | 初始库存 | 每游戏秒固定产量 | 容量 | 达到满仓的经济年龄 |
| --- | ---: | ---: | ---: | ---: |
| 金属 | 500 | 5 | 50,000 | 9,900 秒 |
| 晶体 | 250 | 2.5 | 30,000 | 11,900 秒 |
| 重氢 | 0 | 1 | 10,000 | 10,000 秒 |

**以上全部为本段拟定值，未声称经过长期平衡验证。** 其用途是提供容易独立核算、能观察增长且有严格上限的第一段基线。

对每种资源，唯一领域事实为：

```text
库存(经济年龄) = min(容量, 初始库存 + 固定产量 × 经济年龄)
累计实际入库产出 = 库存 - 初始库存
实际消耗 = 0
```

初始库存的来源是 NPC 创世资产；其余入库量的来源是上述固定生产。满仓后该资源停产，不能把被容量截断的理论产量记作实际库存或已生产资产。不同资源独立封顶。

本段不调用玩家的 `economy(state)` 计算 NPC 资源，不复制玩家星球。玩家科技、曲率核心、成就、增益、手动采集、生产调节和位置倍率均不改变这些生产参数。NPC 产出不进入玩家钱包、`lifetime`、扩张分、帝国投入、暗物质或成就统计。

因此全局经济年龄加固定模型足以推导每个 NPC 的规范库存；此时无需持久化 1,891 份或更多份相同钱包。领域查询应是纯函数；侦察和 UI 必须消费同一规范结果，不能各自生成展示数值。

## 3. 拟定时间与持久化最小状态

本次候选按已采纳的新规则增加以下状态：

```text
npcEconomy = {
  model: "fixed-production-v1",
  elapsedSeconds: 0
}
```

`elapsedSeconds` 是本段经济已实际采用的游戏秒数；不是墙钟、每个 NPC 的首次访问时间或玩家累计 `totalTime` 的别名。新游戏为 0；范围为有限的 0–11,900，允许合法小数。11,900 秒时三项库存都已满，年龄封顶不会丢失本模型需要的事实。

### 3.1 推进位置

- 每个 `tick` 事件分段只推进一次，采用该段实际正数 `step`：`min(11,900, 当前年龄 + step)`。
- 必须在该段侦察到达结算之前推进。现有 [logic.ts](../src/game/logic.ts) 第 102 行推进 `totalTime`，第 160 行调用 `advanceFleets`，新增推进应在这两者之间完成。
- `tick` 入口对已经到达的零剩余时间舰队进行结算时，只使用当下年龄；不能补一个虚构时间步。
- 不逐段向下取整，不按侦察次数积累时间，不因重复调用查询或格式化函数增加时间。
- 全局年龄达到上限后不再增长；不得因序列化、导出或重载归零。
- 与原引擎一样，任意小数时间输入需要明确数值精度验收；不能将浮点细微差异宣传为所有不同切段的整档字节相等。恰好可表示的时间金标应精确验证。

单独保存有界年龄，避免用可能很大的 `totalTime` 减去新起点造成小时间步丢失，也避免升级旧局时把整个历史游玩时间补算为 NPC 产出。

### 3.2 离线与冻结

- 只接收原有 `catchUp` 已封顶的模拟时间。既有上限为 `min(8 小时, 2 小时 + 已保存的离线加成)`；曲率科技可提升该加成，见 [offline.ts](../src/core/offline.ts) 第 43–48 行与 [prestige/tree.ts](../src/prestige/tree.ts) 第 89 行。它改变可采用的全局离线时长，不改变 NPC 每秒生产参数。
- 不另用 `Date.now()`、`savedAt`、NPC 最近查看时间或消息时间做第二次结算。
- `AccountedClock` 采用一次封顶结果后消费原始时间间隔。超出上限的时间不排队，不允许连续刷新分批补领。
- 存档保护、跨标签冲突或失败写入造成的既有冻结同时冻结 NPC 年龄。查看已有快照无副作用。

## 4. 拟定观察合同

### 4.1 抵达之前

银河继续只公开现有身份和侦察入口。选择 NPC、查看派遣报价、发送舰队、读取在途状态都不公开实时库存或提前生成报告。不能将侦察按钮变成免飞行、免燃料的实时查询。

现有飞行时长、探针前置、船舱、燃料、槽位和返航规则不变。NPC 经济不得解锁新的任务种类。

### 4.2 抵达时的静态快照

仅真实出航侦察舰队抵达合法 NPC 目标时，以这一事件边界的年龄生成快照，至少含：

- NPC ID、名称、派系和坐标；身份由现有 `npcAt` 决定。
- 观察的游戏时间及经济年龄。
- 三项实际库存、容量、固定每秒产量及满仓停产状态。
- “抵达时快照”的明确说明；不把历史报告称作当前库存。

最小实现可以复用既有 `FleetMessage { id, at, text }`：用规范领域结果生成一次固定文本，沿用 `scout-舰队ID` 和游戏时间 `at`。领域计算保留小数；显示若做舍入，应明确精度，不能借显示舍入改变库存。

不必为第一段添加第二个报告数组或持久化实时 UI 缓存。消息仍保留最近 150 条，每条文本仍符合现有 1,000 字符限制。已有消息保持原样；旧的身份侦察消息不伪造补上历史库存。

### 4.3 再次侦察及幂等

- 第二次真实抵达产生第二份快照；第一份不会按新时间改写。
- 同时抵达同一 NPC 的两支侦察舰队使用同一经济年龄。处理顺序不能改变库存。
- 重复到达处理、返航、重载和打开消息页不会再增加报告或发放资源。
- 尚未抵达即召回，不产生 NPC 情报；往返燃料沿用原规则，不新增退款。
- 对空位和己方目标继续使用已有报告，不展示不存在的 NPC 库存。

## 5. 拟定数量与计算预算

- 25% 是散列阈值造成的平均占位密度，不是硬性 1,875 个 NPC 上限。整个合法行星空间只有 7,500 格，母星/己方排除仍按原规则执行。
- NPC 经济状态为一个有界对象，不加入 `GameState.planets`；不实例化全图建筑、船厂、研究、协议或逐帧钱包。
- 每个模拟分段新增年龄推进成本 O(1)；单个经济查询新增固定三资源计算。现有 `npcAt` 的己方星球占位检查保持其原有上限。
- 银河页面只查询当前显示的坐标；不为经济基线做全图扫描。现有消息保留策略给侦察存储提供上限。
- 不建立“浏览过的 NPC”无限缓存，不按首次侦察增加持久化钱包对象。

生产档本身不需要随机数。现有 `coordinateRandom` 的占位/派系盐值不变；不得消费 `arcade.seed`、星环票号或 `deepSpace` 的随机游标。未来若增加 NPC 专用档位随机性，需要另行冻结专用散列域及版本，不能复用星环结果流。

## 6. 拟定重置、导入与迁移

### 6.1 曲率与完整新游戏分开

- 曲率保留同一宇宙中的 `npcEconomy`，包括年龄和模型；玩家进度重置不能重新领取 NPC 初态或刷新其库存。曲率预览同样纯读，不推进年龄。
- 完整重新开始建立新局，NPC 经济年龄清零。
- 导入有效存档替换整个世界，采用该文件的模型、年龄、宇宙和消息；不合并身份、快照或经济年龄。

### 6.2 需要加性修订，但文档不升版

年龄和模型是新的持久化事实。本次独立候选采用 v9/r12 加性修订，只有候选完整验收及发布后才会用于试玩站；发布前仍保留已验收 r11。`infinity-original-p4` schema 和 `infinity.original-p4.save.v1` 键保持不变。

当前格式必须严格要求已知模型及有限合法年龄；缺失、非数字、负数、超上限、未知模型、对象多余字段或错误位置应拒绝，不能默默填 0。合法性验证是单机存档结构合同，不声称能证明用户从未手动编辑存档。

### 6.3 真实旧字段迁移

1. 仅处理当前明确支持的真实同源旧格式，保留完整原有迁移和跨引用校验。
2. 在合法旧状态上仅添加 `npcEconomy`，模型为 `fixed-production-v1`，年龄为 0。不根据旧 `totalTime`、玩家矿场、NPC 名字或旧侦察文案推断历史经济。
3. 升级启动仍允许现有 `lastTickAt` 之后的那一次合法封顶离线结算。因而旧文件迁移本身为 0，随后启动可能产生最多该次离线上限内的 NPC 产出；两步须分别验证、分别描述。
4. 不改变原有 `universe`、`totalTime`、`nextFleetId`、舰队、消息、星环/深空随机状态、票据、计划授权、付款工作、拆除槽和地形改造账本。
5. 旧修订夹带专属新字段 `npcEconomy` 必须拒绝，不能静默剥离；不要误把通用 `model` 字段名称在其他领域的合法使用一概禁止。
6. 未知 schema、未来修订、不兼容路线继续保护。另一条 v9/r6 路线的 `sector` 不是本路线的旧 NPC 钱包，不能为了迁移本段而予以接受。
7. 原始字节备份、写入、读回及冻结行为仍由 SaveSession 管理；失败不表示升级完成，不覆盖唯一原件。

## 7. 未来可变账本的强制边界

本模型能用年龄推导库存，**仅因为没有任何扣减或状态变更**。它没有实现玩家掠夺、NPC 建筑升级消费、交易、主动消耗或战损。

以后开放任意库存扣减或不同生产参数之前，必须先设计并迁移到可变账本：保存目标的真实剩余库存、已处理生产时间水位、消费/转移身份及幂等凭证，并明确全图数量和持久化上限。迁移应以同一合法时间点的旧模型实际库存作为一次起点，不能重领初始资产。

**严禁在发生扣减后继续用 `初始库存 + 产量 × 全局年龄` 覆盖真实钱包。** 这会在再次查看、侦察或重载时补回已掠夺资源或已用于升级的库存。容量封顶也不能为这种回补提供理由。未来“扣减 → 推进 → 重载不回补”必须单独通过后，才可开放扣减玩法。

本段不提前加入这些未来字段、奖励或攻击按钮。后续机制、消费价格、成长曲线和排名口径另行定稿。
