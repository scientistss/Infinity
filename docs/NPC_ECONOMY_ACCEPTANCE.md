# NPC 可侦察经济基线：待实施验收合同

## 状态

**本文件定义未来必须提供的证据，不是测试通过报告。** 配套设计见 [NPC_ECONOMY.md](NPC_ECONOMY.md)。固定只读来源为 [`52e7ed83a24f96dbdd240b4e0e4216c63fd90d55`](https://github.com/scientistss/Infinity/commit/52e7ed83a24f96dbdd240b4e0e4216c63fd90d55)。编写这两份文档不代表实现、升存档修订、运行测试或部署。

本段可验收的结论只有“NPC 可侦察经济基线”。即使所有下列项目通过，也不代表完整 NPC 经济、成长、排名奖励或行星战争完成。

## 1. 来源与验收分类

每份实现验收报告至少记录：实际运行源码 commit、相关源文件摘要、工作区状态、执行环境、输入存档原字节摘要、命令及退出状态、结果文件和浏览器来源。不得把脚本存在、文档公式或另一个提交的 CI 当作本提交通过。

必须区分：

1. **独立数值金标**：根据冻结的设计参数计算，不能调用待验收生产函数生成期望值。
2. **领域合成边界**：可构造明确标记的测试状态，用来穷举边界；不能称为自然新号路线。
3. **真实历史来源迁移**：由对应历史源码实际导出的封套，不是当前存档改版本号。
4. **真实操作连续路线**：探针、燃料、出发、抵达、再侦察、存档重载有连续来源，不用写报告字段替代实际派遣。
5. **浏览器证据**：生产包、真实 HTTP 和 native localStorage；受控时钟或故障注入须单独标注。内存 Storage 或内联包只能作为补充，不能冒充原生存档验证。

## 2. 冻结的独立数值金标

金属、晶体、重氢的初态分别为 500、250、0；每秒产量为 5、2.5、1；容量为 50,000、30,000、10,000。所有数值均为本段拟定。

| 经济年龄 | 金属 | 晶体 | 重氢 | 必须说明的状态 |
| ---: | ---: | ---: | ---: | --- |
| 0 | 500 | 250 | 0 | 无历史补产 |
| 0.25 | 501.25 | 250.625 | 0.25 | 小数产出不按段取整 |
| 60 | 800 | 400 | 60 | 可观察增长 |
| 7,200 | 36,500 | 18,250 | 7,200 | 一次基础离线上限 |
| 9,900 | 50,000 | 25,000 | 9,900 | 仅金属已满 |
| 10,000 | 50,000 | 25,250 | 10,000 | 金属、重氢已满 |
| 11,900 | 50,000 | 30,000 | 10,000 | 全部已满 |
| 请求继续推进至 28,800 | 50,000 | 30,000 | 10,000 | NPC 年龄保留 11,900；其余游戏时间照常推进 |

每个资源独立检查：`库存 - 初始库存 = 实际入库产出`，消耗为 0，库存不超过容量。不能把理论产量被容量截断的部分计入实际入库，也不能流入玩家 `lifetime`。

规范库存计算、侦察文本和 UI 展示必须由同一领域结果衔接。验收期望不能从待测侦察文本反解析出来再与自身比较。

## 3. 身份、占位与 RNG 隔离

- 原 `npcAt` 对固定种子、坐标的占位、名称、派系、ID 不变；NPC ID 与 `npc-G:S:P` 一致。
- 母星、己方星球、深空第 16 位和非法坐标不产生 NPC 经济结果。
- 25% 只作为密度规则验证，不能断言每个种子恰有 1,875 个 NPC。
- 遍历合法空间仅用于测试，不进入每帧生产路径。
- 同一合法状态重复查询、切换银河、查看报价、查看历史消息前后，序列化状态完全不变。
- 查询数量和顺序不改变 `arcade.seed`、票号、待开奖结果、押注、保底、自动授权、深空随机游标和报告。
- 玩家产量增益、研究、核心、成就、选中星球与生产比例改变后，给定相同 NPC 年龄的规范库存仍相同。

可复核的定位样例：对 seed `20261010`，独立按现有 32 位散列公式计算得到母星 `[1:56:11]`、同星系 NPC `[1:56:6]` 与 `[1:56:15]`；只排除母星时全图计数为 1,891。它是只读 Python 位运算交叉核算结果，**尚不是生产 TypeScript 的运行证明**；实际实现必须用原生产占位函数交叉验证，不能为匹配样例改占位规则。

## 4. 两次真实侦察的连续闭环

### 4.1 输入与获得能力

选择一个尚未全满仓的合法 NPC。输入可以是有确切出处的历史连续路线存档或明确标记的合成边界存档；两者不能混称自然开局。

核心操作路线必须用真实舰船库存及付款路径：如来源尚无探针，应完成实际前置并真实支付、建成探针。记录付款、造船、燃料余额、目标坐标、舰队 ID、锁定时长和出发时间。不能手工增加舰队、跳过燃料扣除或直接插入侦察消息来代替这条路线。

### 4.2 首次抵达

1. 出发前的银河、报价和在途 UI 不含实时库存；也没有未来报告。
2. 出发只按原报价消耗舰船可用量和燃料，不改变 NPC 年龄或库存。
3. 使用实际锁定飞行时长推进到抵达；当段 NPC 年龄已推进后才取快照。
4. `scout-舰队ID` 只出现一次；坐标、身份、时间、库存、容量、产量与独立预期相符。
5. 舰队进入正常返航；NPC 资源没有转为货物或玩家收益。

### 4.3 第二次抵达与重载

1. 按真实规则返航，再派同一目标或用另一支合法探针舰队发起第二次侦察。
2. 记录实际采用的时间差，独立计算第二次到达库存；未满仓部分必须有相应增长。
3. 第一次报告文本与时间完全不变，第二次是新舰队身份的新快照。
4. 在第二次在途时保存，再从实际保存的状态重载继续；结果与未中断参照路径一致。
5. 抵达后再次保存/重载，报告与规范库存保持一致；再读消息不推进经济或生成新消息。
6. 保存证据中保留 NPC 年龄、模型、报告、舰队阶段以及玩家/随机状态投影，不能只有截图。

不存在第一条报告必须发生在经济年龄 0 的要求：真实探针飞行需要时间。年龄 0 的初态由独立领域金标验证；玩家看到的是实际第一次抵达时快照，不能倒填为 0 秒。

## 5. 时间边界、封顶和幂等

### 5.1 分段与到达顺序

- 使用 0.25 秒等恰好可表示的输入，对一次长 tick、多次短 tick、分段保存再继续进行精确数值金标验证。
- 对真实飞行小数和帧间隔，独立核算采用时间总和并报告误差；实施前冻结数值容差，不能看到失败后放宽。不能把大数库或 UI 舍入误差变成额外产出。
- NPC 推进必须每个全局分段一次，与玩家星球数量无关；双星球不能生产两倍年龄。
- 到达时间恰逢金属、重氢、晶体满仓边界时分别取到正确快照。
- 两支同一时刻到达同一 NPC 的侦察报告库存相同，舰队处理顺序只影响既有消息顺序。
- 零/负/非有限时间不增加年龄；既有已经到达事件只能按其当前边界结算。

### 5.2 幂等与召回

- 重复执行到达处理不重复生成同 ID 报告，不增加年龄，不复制舰船或资源。
- 抵达前召回没有 NPC 经济报告；沿用原燃料不退和返航规则。
- 已返航舰队不重新侦察；从返航存档重载不重放为新观察。
- 空位、己方目标、深空与非法坐标不获得伪造 NPC 库存。
- 第 151 条消息进入后，按原保留策略裁剪；不存在隐藏的无限报告列表。

### 5.3 离线一次

上限沿用曲率科技/已保存的离线加成规则：`min(8 小时, 2 小时 + 加成)`。至少分别覆盖新状态年龄 0 时：

- 原始离线 100,000 秒、基础上限：只采用 7,200 秒，库存为对应金标。
- 原始离线 100,000 秒、合法最高上限：整体游戏采用 28,800 秒，NPC 年龄封顶 11,900；其余领域仍走原规则。
- 负向墙钟或非法 elapsed 按现有逻辑采用 0。
- 保存封顶结果后立即重载，以及连续刷新，不能继续领取第一次被截掉的时间。
- native 后台恢复、保存水位与 NPC 年龄只推进一次；受控时钟边界与原生生命周期证据分别记录。

## 6. 曲率、新游戏、导入分别验收

不能用一种“重置”测试代替以下三种语义：

| 场景 | 必须保持 | 必须变化 |
| --- | --- | --- |
| 真实曲率 | 同一 universe、NPC 模型和年龄、同坐标规范库存、保留的历史消息 | 玩家世界按原曲率规则更新；无新 NPC 初态赠送 |
| 完整新游戏 | 只遵循新局既有创世规则 | NPC 年龄为 0；不能带入旧消息或旧世界年龄 |
| 导入另一个合法文件 | 采用该文件自己的宇宙、模型、年龄和消息 | 替换当前局，不能拼接两个世界或取较大年龄 |

曲率预览、失败的曲率条件、失败的新游戏事务、失败导入和晚到的旧 UI 事件都不得改变 NPC 状态。保护态查看只读页面不得继续推进。

## 7. 真正旧格式与新格式校验

### 7.1 旧档迁移自身为 0

优先固定现有真实文件 [demolition-origin-r10-save.json](../tests/fixtures/demolition-origin-r10-save.json)，出处见 [demolition-origin-provenance.json](../tests/fixtures/demolition-origin-provenance.json)。

- 来源：`ac3cce98403bea1e7162bcb4092e4cfeeb448a9a`。
- 原 SHA-256：`d456cbee26543071ce0a53b64f718dd707c59b4f47ccb5c07d10a292cd45aa2a`。
- 原字段：v9/r10、`totalTime = "25810"`、seed `20261010`、`nextFleetId = 4`；没有 `npcEconomy`。

不含启动补算的纯迁移必须：新增模型及年龄 0；保存全部旧状态投影；不按 25,810 秒生成满仓库存。原封套字节及 hash 必须保持，不能为了令离线为 0 而编辑历史文件。纯迁移可以直接使用合法导入路径；隔离启动补算时可给测试启动提供与原水位匹配的时钟，并明确标记受控时钟。

r11 使用最终精确源码实际导出的输入，必须覆盖实际未完工拆除的费用、来源、稳定 ID、剩余时间和地形改造既有账本。旧 r2–r9 保留已有真实源迁移门禁。不能仅检查最新空白档，也不能通过改 revision 生成历史源。

### 7.2 升级启动的一次补算单独验证

在同一真实旧封套上运行完整 SaveSession 启动：先合法迁移年龄 0，再按原 `lastTickAt` 计算一次受限离线。分别核对迁移前、迁移后未补算、启动补算后与持久化重载后。只有合法旧玩家工作和原已授权计划按既有规则继续，不因 NPC 迁移获得新授权。

### 7.3 严格读取与故障

- 新格式缺对象、未知模型、年龄类型错误、负数、非有限值、超 11,900、多余字段或字段放错位置均拒绝。
- 旧 revision 夹带专属 `npcEconomy` 字段，即使为空或 null 也拒绝；不误伤其他领域的通用字段名。
- 未来 revision 和不兼容 schema 拒绝；另一条 v9/r6 的 `sector` 继续拒绝，不能作为 NPC 历史来源。
- 当前完整导出 → 导入 → 再导出在相同封套时间下稳定；NPC 状态和历史报告不刷新、不重抽。
- 备份写入/读回失败、当前写入 throw/drop、写后读回拒绝、跨标签变化分别覆盖。可读旧状态保持冻结，原件可导出；不确定写入不得声称磁盘完全未变或升级已完成。
- 对已经采用的封顶离线结果重载，不重复采用历史间隔；对失败且未采用的事务不冒充已完成。
- 旧读取器必须拒绝新的实际修订，而不是悄悄丢掉 NPC 年龄后接受。

## 8. 不污染旧玩法及性能预算

- 用匹配输入比较引入本段前后的完整旧字段投影；除了新增侦察文本的明确变化，旧经济、支付、舰队、队列、曲率、星环和深空行为保持原规则。
- NPC 查询不增加玩家库存、`lifetime`、积分、成就、暗物质、任务授权或星环收益；使用存在真实侦察成本的对照，不能要求玩家燃料凭空不变。
- 不新增攻击任务、领奖入口或未定义资源转移；当前原始 UI/美术与星环保护门禁继续运行。
- tick 新增固定年龄操作，不能全图遍历 NPC；银河显示查询量只随当前视图变化，消息展示随保留上限变化。
- 保存体积新增一个有界对象与已有消息范围内的文本；对大量重复浏览、侦察和长时间满仓确认不存在无限缓存或附加日志增长。
- 报告性能实测条件；算法有界不等于任何设备上已达到极限流畅。

## 9. 未来开放扣减前的门禁

第一段没有库存扣减，不能用本段测试替代可变账本验证。将来接入掠夺、建筑升级消费或交易前，至少必须另外证明：

1. 从本模型的同一合法时间点实际库存迁移一次，不重发初始资源。
2. 真实扣减只应用一次；对方入账或在途资源有对应身份和守恒。
3. 扣减后的查看、侦察、tick、导出和重载都不会按全局年龄公式补回被扣资源。
4. 新生产只从已处理水位之后累加，并服从容量及已冻结的生产参数。
5. 重复请求、离线、曲率和旧存档迁移不能复活已掠夺或已消费库存。

在该门禁通过前，不开放任何消费、攻击、掠夺、排名奖励或动态 NPC 成长。本文件只保留这一未来边界，不要求第一段先实现战争账本。
