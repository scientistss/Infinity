## 本次建筑模板跨轮增量

实际创建一份模板 `#1 / revision 1`，且只创建一次；名字和三个绝对目标没有附带星球、预算、运输或执行权。创建前后递归比较整个序列化状态，只允许精确的新模板记录及 `nextTemplateId` 改变，钱包、任务、队列、job／work 计数器及时间完全不变。两代均先调用只读映射和两次显式报价，要求完整输入不变、重复报价完全一致，三个目标都从 0 级且没有已付队列开始。

每代独立核查逐级向下取整后的固定 golden，不能以报价自身当作预期：

- 金属矿 0→3：285M / 70C / 0D
- 晶体矿 0→2：124M / 62C / 0D
- 太阳能电站 0→3：355M / 142C / 0D
- 合计：764M / 274C / 0D

每个新增目标分别传入明确预算。应用前后完整状态比较只允许新增恰好三个普通有限任务、连续增加三个 task ID；旧任务、库、所有钱包／队列、job／work 计数器与时间不变。每项均固定实际殖民地为执行和付款星球，无运输或编成来源，初始 `charged`／`refunded` 为零、`activeJob`／`currentWork` 为空。重复应用已用请求必须拒绝且全状态不变。

## 保存与在途续跑

历史首轮片段为 18 个里程碑；本次增加建筑模板授权和实际付款两个点，首轮为 20 个。每个点分别执行两次严格读回，递归比较整个 `serializeState` 输出：字段存在性、类型、原始数值、数组长度和顺序均不可变，只有对象键插入顺序不属于引擎状态。后续实际从读回对象继续运行。

保存点包括已付款建筑、研究、造船队列，殖民舰在途，以及物流 `pending + outbound`、`pending + returning`、`paid + activeJob` 状态。早期仅首轮的 `08d097d` 报告中，前 17 个点有随后的真实 live tick 证据，最后一个点只证明终态已读回采用。本次同样延续同一状态继续第二片段，另在次代新增授权和实际付款两个点；原有 28 个保存点与所有逐字段比较保持不变。完整路线的保存和后续 tick 总数见下一节。

每个里程碑附带可独立严格导入的匿名存档，报告保留动作、实际钱包、任务与舰队身份、等待原因、报价、付费回执和逐任务核账。任何阻塞会生成失败报告并返回非零退出码；120 游戏分钟为固定策略首轮的硬上限，不为抽取绿色结果而自动追加资源或延长时间。

## 尚未由这些片段证明

这是一次曲率和第二轮重建／职责互换，不包含第二次曲率。此次曲率前没有活动付费队列或在途物流，不能用它证明这些分支的重置清退。旧研究请求原本已因旧 nextTaskId 失效，其拒绝不单独证明跨重置 reviewKey 隔离；另有旧付款星球映射拒绝，以及仍持有效 nextTaskId 的未执行旧编成请求因旧殖民地不存在而拒绝。

评估与实际重置共用生产规则，完整候选相等证明规则一致性，不是两套独立引擎交叉验证。总账核验也不等于每一笔付款都独立观察过各星钱包；研究和第二殖民船／货物有精确钱包证据，建筑模板及编成另核真实付费身份、计划账和最终等级／库存。领域脚本不验证浏览器“保存读回成功后才采用重置”的存储事务，该合同由专门浏览器套件覆盖。

仍未验证所有策略和种子、长期平衡、自然累积十次星环手动结算、真人连续 UI 操作、原生浏览器缓存或实际设备性能。有限模板应用不自带运输授权，首轮路线另行显式创建有单源预算的建造任务，不能据此声称模板复制了物流许可。
