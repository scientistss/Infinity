# 表现与性能验收

## 调度边界

- 普通可见页面最多每 100 毫秒进行一次常规表现更新；不排队补画旧帧。
- 游戏模拟仍按原有 RAF、五秒后台分支、离线上限、协议与计划时钟运行。
- 操作完成立即展示；原生导航、输入、输入法提交和折叠变化在下一 RAF 展示。捕获监听不重绘，不干扰尚未处理的点击或默认行为。
- 隐藏页面跳过昂贵投影，保留更新标记；恢复先按已结算水位处理欠时，再展示最新状态。
- 已冻结的安全存档会话不因时间或动画持续重绘。可操作的星环页面仍每帧更新原动画，包括待机跑灯。
- 自动曲率、成功导入和重置立即退役旧执行权限，不等重绘。失败或取消不重置现有世界。

## 计算范围

`present` 和 `spaceView` 保留完整投影，作为精确比较参考；跨版本比较只对银河页明确的构建版本标签做预期归一，其余字段完整比较；新可见投影复用原公式。资源栏、解锁、星球选择和三类已付款队列仍更新，不宣称隐藏 DOM 完全没有工作。建筑、研究、造船、防御、商店、协议、成就和曲率正文只在相应页面计算。银河、舰队、消息和计划分开投影；模板及编成编辑器还要求折叠区展开。

表单的当前世界引用、预算核对及按钮权限与表现节奏分离。队列使用稳定付费工作 ID；队首改变会立即刷新，暗物质加速还检查上次显示的队首，避免把工作 A 的按钮转给工作 B。初次隐藏的付款/来源默认值仍来自启动世界，而不是第一次打开表单时的世界。

## 可重复的压力档

`scripts/performance-fixture.ts` 生成匿名合成档。明确预置初始资产与完成的科技/建筑；其后殖民、计划、付款、运输、回执、舰队、模板和编成身份都通过真实 API 产生。组合包含：

- 100 颗星球（含 99 颗真实殖民地）、1000 支真实航班，其中 16 支属于计划运输
- 100 个保留计划：60 完成、8 取消、32 运行
- 256 条真实回执：240 已送达返港，16 在途
- 200 项建筑、1000 项造船批次和 2 项研究，共 1202 项真实已付工作
- 32 个模板 × 16 科技目标、32 个编成 × 13 可飞行舰种

保存文本同时报告精确 UTF-8 字节、JavaScript UTF-16 字符数、SHA-256 和紧凑 JSON 指标。示例本地生成的正常缩进导出约 1.91 MB；原生当前槽加备份仍须按浏览器实际配额验证。集合已满时不能继续派遣或授权，不把“严格可读”误称为“所有操作仍可用”。不包括 100 支计划舰队、深空任务极限或读取器容许但非自然产生的 8000 残骸项等额外边界。

## 分层证据

1. 单元与领域：冻结输入、各页面完整字段等价、60/120Hz 表现上限、稳定身份和世界更换。
2. 原生 Node 模型墙钟：同一冻结组合档、固定旧源码 `4a4a4d6`、交错先后、预热后原始样本、中位/P95。导入、导出、模拟分别测量，不纳入表现提速。
3. 受控浏览器正确性：真实 HTTP、原生存储和可信鼠标/键盘/输入法；显式控制时间与 RAF，逐步比较整个引擎状态。记录的是原 view 调用次数，不是 CPU 时间或物理绘制次数。
4. 原生浏览器性能：不替换 Date、performance、RAF、计时器、存储或可见性 API；分别测启动与稳态 CDP CPU 指标、长任务及浏览器事件延迟。每次仅更新保存封套时间，状态负载完全一致，精确种子哈希单独记录。没有任意固定毫秒的 CI 性能门槛。
5. 原生后台与所有既有浏览器套件继续执行，不以新计数测试替代真实隐藏、恢复和重载验收。

初次本地 Node 24 的 30 样本配对测试中，纯模型管线中位时间：设施约 30.60→0.35 ms、银河 30.78→1.07 ms、舰队 30.21→6.02 ms、消息 30.45→0.25 ms、计划 30.24→4.14 ms。该次极限档单个 1/60 秒模拟步骤仍约 55–56 ms，规则与实现未在本阶段优化；不能由这些模型数字推导浏览器帧率。机器、JIT、GC 和负载会影响绝对数值，Actions 归档保留每次实际结果。

## 运行

先安装现有锁文件依赖，准备上述固定提交的只读源码副本及其依赖，再运行：

```sh
npm test -- --maxWorkers=1
npm run build
node --import tsx scripts/performance-fixture.ts > performance-review-save.json
node --import tsx scripts/benchmark-presentation.mjs --fixture performance-review-save.json --before-source /path/to/before > presentation-model-report.json
node --import tsx scripts/render-scheduling-fixture.ts > render-scheduling-review-save.json
```

将旧、新生产包分别经 HTTP 提供至 4174/4173，再运行新增两个浏览器脚本。具体依赖、固定来源和完整命令在 `p4-original-verify.yml`。报告、合成输入、失败截图与精确源码存入对应提交的 Actions 产物。脚本存在或本地单测通过不代表原生浏览器已通过。
